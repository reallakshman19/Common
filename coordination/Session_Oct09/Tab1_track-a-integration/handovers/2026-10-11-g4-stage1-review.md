## 3. Important corrections and cautions, with evidence
1. **A verified print failure is not a proven CSS/event causal chain.** An older browser run on raw `4760cfb5` measured screen width 728 against 488 print host, but `fitFigure()`'s `ResizeObserver` scheduling/print callback order is not instrumented. A simple `width: max(100%,needed px)` proposal or synchronous refit may each have tradeoffs: large `needed` can still overflow a narrow A4 column; forcing `max-width:100%` may push mathematical SVG labels below the 14px floor. The incoming authorized engineer must measure viewBox, min font, print host and final factor at first frame **before** selecting source syntax. Fix goal is simultaneously **inside printable support region AND ≥14px measured readable labels**; if impossible at the chosen aspect ratio, escalate a revised figure layout/Owner visual tradeoff, not silently hide it.
2. **An attempt unlock is not a correctness validator.** Source `validAttempt()` can accept filled text, selected multiple choice or an affirmative paper-attempt checkbox. This is appropriate protected answer gating, but do not call a `CORE1B` self-attempt "proven independent reconstruction" without [#168](https://github.com/reallakshman19/Grade9v3.5/issues/168) independent mathematical/educational assessment and a real user review. Distinct Core1B boundary attempt is implemented by `core1b_js()` replacement, yet automated evidence cannot establish learner understanding.
3. **The 14px floor is intention plus limited gates, not current physical acceptance.** `_figure_text_findings()` uses a **reference-tablet projection** and `fitFigure()` computes `needed` from CSS font size; neither guarantees the *immediate printed frame* has all labels legible and within A4.
