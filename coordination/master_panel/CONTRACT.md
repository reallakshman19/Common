## Invariants and observed limitations

* Public allowlist for the first observable slice: repository identity `1412133785 / reallakshman19/Common` and `1363905693 / reallakshman19/AA3` (verified GitHub identities). These are **sources**, not automatic work/agent attribution. Every work/agent comes from a separately explicit, compatible, versioned registry binding. Unknown or unregistered providers stay UNKNOWN/unassigned.
* The stable GitHub object key is `(numeric repo_id, source kind, provider entity_id)`. Use the GitHub numeric comment id for ISSUE_COMMENT, issue id for ISSUE, PR id for PR, check-run id for CHECK_RUN. Issue number is navigation, not globally unique identity. `revision_id` is an observation revision identifier scoped to the stable object key, not authentication of author. Source body `body_sha256` hashes exact UTF-8 bytes.
* A source edit is a new observation when (provider updated_at, body SHA) changes; replay of the same exact observation is idempotent. A→B→A with three distinct edit timestamps must yield three ordered revisions even though only two content digests exist. If the same provider timestamp gives different bodies, mark conflict rather than silently select one. Missing historical timestamps must be typed UNKNOWN and never synthesized as verified identity.
* Full pagination (including resume/restart after partial pages) is necessary before inferring an entity is absent or deleted; failed/partial/permission-limited scans keep the previous known row, mark source unavailable and do not emit a tombstone. After a completed consistent scan, absence is `ABSENT` and history is retained, never hard deleted.
* Provider status per source is independent: REACHABLE/PARTIAL/RATE_LIMITED/FORBIDDEN/UNAVAILABLE/UNKNOWN; freshness is FRESH/STALE/UNKNOWN and must be clock/source-grounded. Missing does **not** mean zero or offline. 401 remains authentication failure, 403 authorization, 429 rate-limit and 5xx unavailable in intake error metadata. Per-repo failures cannot erase another repository.
* CASP 1.0.0 fenced public issue-comment reports may be parsed into strictly whitelisted `kind, reported_status, message_id, request_id, sender_id, project_id, work_id, assignment_id, run_id, lane_id, candidate_sha` only when repository ID/name, mailbox issue and project target agree with the observed GitHub source. This is explicitly `PROVIDER_REPORT` data, **not** a coordinator-approved registration, authenticated sender identity, independent reviewer verdict or agent run observation. Free-text `payload.text`, private refs/chat IDs, tokens and untrusted body content are never published/stored as a public report. Unsupported or ambiguous envelopes leave claims UNKNOWN. The trusted `bindings` integration is caller-supplied and currently NOT_CONFIGURED.
* Provider report, coordinator observation and independent evidence review are disjoint provenance layers. A provider's PASS cannot be independent review. A reviewer verdict requires a separately attributed review ref. An OLD_HEAD review is historical, never current-head approval. Skipped/path-scoped CI is `NOT_APPLICABLE`, not PASS. No new universal native workflow/stage evaluator.
* Privacy: public rows are whitelisted typed IDs/statuses, canonical public GitHub URLs and digests. They do not contain raw body, tokens, private owner command queue, private chat/browser URL, cookies, local paths or unfiltered free prose. Never expose `command_db` through a public endpoint.

## Exact public row shape

`coordination/master_panel/models.py` implements `build_row`. Consumers MUST negotiate `schema_version == "1.0.0"`; unknown fields/versions must not be silently interpreted as acceptance.

| Field | Type and meaning |
|---|---|
| `schema_version` | exact string `1.0.0` |
| `source` | `{project_id,repo_id,repo_full_name,kind,entity_id,revision_id,issue_number?,comment_id?,body_sha256?,created_at_utc?,updated_at_utc?,url?}`; stable object and revision source |
| `binding` | `{state: BOUND/UNASSIGNED/CONFLICT, project_id, work_id?,lane_id?,assignment_id?,run_id?,provider_kind,conflicts:[]}` |
| `report` | `{provenance: PROVIDER_REPORT, task_id?,candidate_sha?,reported_status?,kind?,message_id?,request_id?,sender_id?,reported_work_id?,reported_assignment_id?,reported_run_id?,reported_lane_id?}`; source-scope-validated nullable claims, **not** trusted identity, liveness or acceptance |
| `coordinator_observation` | `{provenance: COORDINATOR_OBSERVATION, observed_at_utc?,liveness: ALIVE/STALE/STOPPED/UNKNOWN,probe_status?,source_ref?}`; independent of GitHub silence |
| `evidence` | `{reported_verdict,review_verdict,review_ref?,review_candidate_sha?,current_pr_head_sha?,candidate_relation:CURRENT/OLD_HEAD/UNKNOWN,applicability:APPLICABLE/NOT_APPLICABLE/UNKNOWN}` |

### Codex F04/F06 correction profile

Duplicate JSON fields and invalid calendar times are rejected. Full correlated/trusted attribution qualification remains separate.

## F07-A2 private durable recorder candidate

`casp_store.py` records exact public-comment bytes, provider actor observations, supplied descriptor/request bytes and their separate fingerprints in private local SQLite. Source versions and capture receipts are append-only, atomic and restart-safe. Replay does not rewrite a version; A-to-B-to-A source edits preserve their ordered versions. Conflicting provider revision/timestamps, message IDs and scoped request keys stay explicit. A later invalid source/context cannot silently fall back to a prior valid claim. History reads are bounded and source-scoped.

Schema-valid source identities remain indexed even when supplied correlation fails; this does not borrow successful correlation. Older or unknown provider timestamps are retained as non-current captures rather than replacing a newer ordered source. Equal provider instants are compared in UTC while exact source text remains unchanged. Provider actor IDs are positive ASCII decimals bounded to20digits, observed metadata rather than authenticated per-agent identity.

Supplied descriptor/request matching is structural context, not registry admission or authenticated sender identity. REVIEW/ACCEPTED and INVALIDATION are recorded claims; the recorder applies neither acceptance nor invalidation authority. Raw payload, evidence and context prose remain private. Only safe structural identifiers, hashes, dispositions and bounded provider actor observations are returned; authentication, current applicability, independent acceptance and liveness remain UNKNOWN. Schema-integrity failures stop recording rather than weakening validation.

This isolated recorder is not yet wired into the scanner, source registry or public API. F07-B integration, externally independent exact-head qualification, full C1/C4 and M2 release remain pending. It grants no command, worker, publication, deployment or writer authority.

Enumeration completion is distinct from absence proof. Resumed scans and collections spanning offset pages preserve unseen rows and report `absence_verified:false` plus durable `ABSENCE_UNVERIFIED`. Only uninterrupted single-page collection enumeration permits observed-absence tombstones. This conservative policy may retain truly absent records until absence is qualified; it does not manufacture a GitHub deletion time or solve live multi-page snapshot parity. Existing independent fixtures/oracles remain unchanged.
