# WP4 — Secure Hosted Interactive Dashboard & Sanitized Public Snapshot Exporter

**Scope:** Issue [#353](https://github.com/reallakshman19/Common/issues/353), Workpack 4 (WP4).

WP4 delivers the visual interface and sanitized public export for the Control Tower v3:
1. **Public Snapshot Exporter (`coordination/public_exporter.py`)**: Generates deterministic, leak-free static snapshots (`CONTROL_TOWER_PUBLIC_SNAPSHOT_V1`) from precomputed WP3 materialized projection read tables.
2. **Hardened Front-End (`coordination/ui/`)**: Operates in dual-mode (Local Stored Projection via private loopback API vs Static Published Snapshot on GitHub Pages).

---

## 1. Dual-Surface Disclosure Boundary

| Attribute | Local Owner Cockpit | Public Static Dashboard |
|---|---|---|
| **Access Model** | Unauthenticated local loopback (`http://127.0.0.1:8765/`) | Static hosting / GitHub Pages |
| **Data Producer** | `GET /api/v3/projections` reading precomputed SQLite read tables | Static `public_snapshot.json` generated by `public_exporter.py` |
| **Approved Projects** | All registered projects | Explicitly selected projects only (`--approved-project` CLI; no implicit public project selection) |
| **Coordinator Next** | Preserved verbatim | **WITHHELD** (`[WITHHELD_PRIVATE_COORDINATOR_NEXT]`) |
| **Internal Identifiers**| Full internal entity IDs and digests | Stripped (`chat_id`, session tokens, internal digests omitted) |
| **Link Security** | Internal & external links | Only verified HTTPS links to approved domains (`github.com`) |
| **UI Freshness Label** | `LOCAL STORED PROJECTION` | `STATIC PUBLISHED SNAPSHOT` |
| **Failure Mode** | Displays explicit 503/404 error; **no silent fallback** | Displays offline/unavailable banner |

## 2. Public Snapshot CLI Usage

To generate a public snapshot:

```bash
python -m coordination.public_exporter \
  --projection-db /path/to/projection_index.db \
  --output-json /path/to/public_snapshot.json \
  --approved-project common
```

Or via Python API:

```python
from coordination.public_exporter import export_public_snapshot

snapshot = export_public_snapshot(
    projection_db_path="projection_index.db",
    output_path="coordination/ui/public_snapshot.json",
    approved_projects=["common"],
    policy_version="v1.0.0"
)
```

### Sequential 4-Stage Privacy Pipeline
1. **Authorization Gate**: Filters entities against `approved_projects`.
2. **Projection Gate**: Applies strict allowlists per view (`PORTFOLIO`, `WORKS`, `ASSIGNMENTS`, `EVIDENCE`, `RECOVERY`), sanitizes URLs via `URLSanitizer`, withholds private `next` instructions and internal detailed per-job PR check observations.
3. **Validation & Leak Scan**:
   - Validates against `coordination/schemas/control_tower_public_snapshot_v1.schema.json` (`additionalProperties: false`).
   - Recursively executes `PrivacyValidator.assert_no_leaks`: hard failure on any token (`ghp_`, `Bearer`), private key, local filesystem path (`C:\Users\...`, `/home/...`), or forbidden key name.
4. **Atomic Promotion**: Writes to `.tmp.<pid>` with `fsync`, calculates deterministic content digest, and atomically renames (`os.replace`) to target output path.

## 3. Front-End Architecture (`coordination/ui/`)

- **Zero External Dependencies**: All external fonts removed; uses system font stack.
- **Strict Content Security Policy (CSP)**:
  `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self';`
- **Safe DOM Construction**: Pure `document.createElement()` and `textContent` DOM nodes; zero dynamic `innerHTML`.
- **Subpath Relative URLs**: Compatible with GitHub Pages subdirectory hosting.
- **Views**:
  - **Portfolio**: Multi-project overview, provider reachability, work count, active assignments, coordinator source state.
  - **Works**: Work ID, AIM label SHA, candidate PR, exact-head CI badges, Owner acceptance status.
  - **Assignments**: Authoritative 10-column coordinator display table (`Tab`, `Status`, `Aim`, `Plan`, `AC`, `CI`, `Meter`, `Due`, `Checked`, `Next`).
  - **Evidence**: Canonical task evidence with candidate text, proof links, and explicit attribution status.
  - **Recovery**: Factual anomaly log with verbatim coordinator next actions.
  - **Unassigned Observations**: Unmapped tab observations visible in local Owner cockpit.


## 4. Publication and freshness limitations

Public hosting is approved in principle; **no live private SQLite file or automatically refreshed Owner dashboard is published by a Git merge**. An operator runs the exporter against a trusted private WP3 materialized DB, inspects the resulting public JSON, and publishes **only** the static UI assets and that validated JSON. The project list in repeated `--approved-project` flags is the current publication selection mechanism; a standalone `publication_policy.json` file has not been implemented.

- The static dashboard uses `./public_snapshot.json` relative to its Pages site subdirectory, never a loopback API on viewers' machines.
- For local static preview, run a static HTTP server and open `index.html?mode=static`; direct `file://` fetch is not a supported mode.
- A local Owner instance on loopback uses the stored WP3 read-only API. It is **not** a live agent heartbeat; stale source timestamps remain explicit.
- Public exports cap evidence to 500 records and any other individual public view to 5,000 records; oversized payloads fail rather than publish misleading partial data. The output is limited to 5 MiB.
- WP5 (Owner-command/delivery plane) is not implemented and Issue #353 remains open.
