## Recommendation for Owner D-AIM-2 (not approved)
The important control is **two-dimensional**, not only size: a candidate **100MiB input-byte bound**, **2000000 original source occurrence bound**, **<=200ms maximum frame gap** measured across source intake, matching, browsing and CSV, and **typed, no-CSV fail-closed** response when either size/event bound exceeded. Additional true peak-memory and cold/warm tests, negative original semantic oracles and deployed Pages evidence needed before final acceptance. At exact HEAD, 100MiB byte-heavy is responsive and complete, but high-cardinality input at even ~59.5MiB is refused, so an unconditional promise to trace *all* 100MiB documents is FALSE. If Owner requires all content <=100MiB, initiate a **separately versioned O1 high-occurrence index module/Worker** with explicit bounded work, indexes, timeouts and memory tests rather than casually removing old protected guards or patching old XML/Preview/Weight algorithms.
