## Failure diagnosis decision tree (do not guess repairs)

```text
Does fresh current Worker receipt match original index/selection/masters?
  No -> source/lease/basis diagnostic. Preserve original and decisions, refresh only as governed.
  Yes -> are verified physical facts and Final mass decisions complete?
    No -> show missing/match1/unresolved group, do NOT zero or auto-approve.
    Yes -> did native Final intent become eligible?
      No -> diagnose Final intent on the same source-bound Worker.
      Yes -> did actual guarded native converter yield ok + CII bytes + diagnostic?
        No -> use PR #336 safe category + phase; reproduce engine failure.
        Yes -> did independent parser verify CII, owners, mass and current Final intent?
          No -> HOLD, preserve byte/lineage witnesses, fix bounded provenance or writer defect.
          Yes -> offer gated Download CII for this same current live lease.
                  Solver/material/restraint acceptance remains separately scoped.
```

**Do not infer** an engine error from `FINAL_INTENT_NOT_OBSERVED` in an ordinary UI snapshot. A fresh diagnostic can read Final intent; neither it nor 100 Final mass authorizes the output. Conversely, once actual native candidate fails with `NATIVE_CANDIDATE_CONVERTER_FAILED`, the immediate next input is the new allowlisted **phase/category/code** on deployed current main, not an XML topology rewrite.

## Interdependency ledger: three connected tasks + one parallel

1. **Observed native Run failure → deployed safe diagnostic** (Owner trial/revision witness). This closes *observability*, not product output.
2. **Diagnostic → tightly scoped converter repair** (separate builder, protected real fixture custody or explicit NOT_RUN). This closes the specific engine/packing fault without changing accepted Final, worker lease or release guards.
3. **Repair → independent actual-CII mass/lineage + Owner use** (separate reviewer under native authority). This closes only the tested output/Download path; preserve importer/solver/material/restraint limits.
4. **Parallel:** independent CAESAR II contracted-model challenge for draft PR #335. Its result is **not** a shortcut to 1–3 and cannot be imported from a historical no-op.

## Architectural change discipline

Before altering production source, successor checks (a) exact current branch/head, (b) Owner-approved source/model and eligible input bytes, (c) which Worker or app owns the state, (d) original/physical/CII row identity, (e) expected failing negative and correct positive, (f) served `docs/` mirror dependencies, (g) native CI / real browser acceptance, and (h) distinct engineering and release authority. If an algorithm change would transform a claim from strict 1:1 mass ownership into a multi-split rule or release a previously blocked auxiliary CII reference, **that is a new engineering contract**, not a cosmetic bug fix.
