# Programme bootstrap / zero-context reconstruction

Use when ChatGPT Work first enters a programme, after a long gap, after coordinator/session loss, or when the Owner asks for a fresh programme picture.

This is read/reconcile work. It grants no engineering authority.

```text
PROGRAMME BOOTSTRAP

1. Read the parent programme issue completely.

Recover:
- Owner outcome;
- why-now / governing witnesses;
- non-goals;
- current programme basis revision;
- effective amendment index;
- canonical inputs/source authority;
- programme invariants;
- workstream registry;
- producer/consumer contracts;
- dependency contracts;
- EXIT criteria;
- decision surface.

2. Read each effective Owner/programme amendment referenced by the parent.

Do not treat ordinary comments as programme amendments.

3. Read the dedicated [Relay Handover] child.

Treat it as an operational index only.
Do not trust claims that are contradicted by current durable evidence.

4. Enumerate every child implementation issue and every nonterminal PR.

Carry draft/open/conflicted/changes-requested PRs until terminal.

5. Read current implementation-plan refs/revisions.

Classify:
PRESENT
MISSING
STALE
UNKNOWN

A missing/stale plan reduces reconstruction confidence only.

6. Verify material reality where it matters:

- current main;
- branch/head;
- PR lifecycle/mergeability;
- commits/diffs;
- tests/runtime/artifacts;
- durable handoffs;
- programme-significant local coordinator/helper returns.

7. Recover negative knowledge.

Do not reopen rejected approaches unless their explicit reopen condition is met.

8. Derive:

OUTCOME GRAPH
OWNERSHIP GRAPH
PRODUCER-CONSUMER GRAPH
DEPENDENCY GRAPH
EXPECTATION GRAPH
MATERIAL GRAPH
EVIDENCE GRAPH
NEGATIVE-KNOWLEDGE GRAPH
DECISION GRAPH
TEMPORAL GRAPH

9. Identify:

- work that can run now;
- work that can run partially;
- actual missing production outputs;
- possible local file/conflict coordination;
- consumer outputs ready to route;
- stale plans that could mislead consumers;
- helper/local-coordinator opportunities;
- unresolved semantic uncertainties;
- genuine Owner decisions;
- next useful observations.

10. Reconcile parent EXIT criteria against exact evidence.

Do not infer programme completion from child issue or PR counts.

OUTPUT

PROGRAMME DESTINATION
CURRENT BASIS
SOURCE FRESHNESS
WORKSTREAMS
PARALLEL-SAFE WORK
PRODUCER → CONSUMER EDGES
MISSING PRODUCTION TRUTH
READY HANDOFFS
EXPECTED NEXT OBSERVABLES
NONTERMINAL PRS
NEGATIVE KNOWLEDGE
PROGRAMME EXIT CRITERIA
SEMANTIC UNCERTAINTIES
OWNER DECISIONS
NEXT COORDINATOR ACTIONS
NEXT USEFUL OBSERVATIONS

Relay rule:
V3.1 only if Relay context is relevant.
Do not consult V3 or V2.5 for live semantics.
```
