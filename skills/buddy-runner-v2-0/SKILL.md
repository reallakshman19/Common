# BuddyRunner v2.0 — Relay with high ROI improvement

Preserve the Owner's aim. Independently reassess the route. Choose the highest justified ROI action. Carry the learning forward.

Read [CONTRACT.md](references/CONTRACT.md) first. Use [ASSISTED.md](references/ASSISTED.md) for a participating predecessor, or [RECOVERY.md](references/RECOVERY.md) without one. ONBOARD is RECOVERY with an explicit wait for the Owner's next task. Use [HOST.md](references/HOST.md) when integrating the Python API with source readers or an executor.

## Activate the requested work

An explicit start request means perform the allowed stage now when actual sources, role and scope are available. Do not replace execution with a progress chart or pretend a generated packet launched another agent.

Select exactly two takeover modes:
- ASSISTED: outgoing G1 prepares 1a with execution HOLD; incoming G2 independently submits 1b; G1 reconciles once into 2.
- RECOVERY: incoming engineer reconstructs and records its own direction; no replacement G1 required.

Select continuation explicitly:
- CONTINUE_AUTHORIZED_TASK: select and perform the justified next task under actual authority.
- AWAIT_OWNER_TASK: submit reconstruction for the Owner's approval, then wait for a new task. Accept ONBOARD as an alias only with this policy.

In onboarding retain full high-ROI analysis; recommendations remain recommendations. Approval alone does not authorize a future unspecified task. A task alone does not imply reconstruction approval. Both can be explicit in one Owner response. Report ONBOARDED_AWAITING_TASK after approval without a task; do not resume an older grant or create timers.

## Require substantive engineering understanding

Use an explicit capable model and High minimum reasoning effort, preferably Extra High where supported. Set both model and effort. Record actual setting evidence and its limits; self-report and response length do not prove configuration. A skill cannot switch the current chat's model.

Reconstruct original purpose, effective Owner amendments, artifacts/approval scope, source/runtime flow, meaningful contributions and responsibilities. Inspect actual code and consumers; summaries and CI counts are claims to test.

Compare the inherited route with credible practical alternatives, including reuse and KEEP. Rank up to three by Owner-outcome gain, recurring friction removed, effort and risk. State source fact versus hypothesis and a smallest falsifier. Do not manufacture an improvement when KEEP is best.

Treat CI, missing receipts and inherited blockers as evidence to understand. Investigate what they actually block and whether a better route removes the dependency. Keep current Owner decisions, real writer ownership and privacy boundaries. Bound actual changes while understanding the whole relevant outcome chain.

A schema checks structure, never semantic judgment. Do not call a generic copied summary a successful takeover.

Keep it on existing authorized issue/index surfaces; return complete NOT_PUBLISHED output when publication is not authorized. Never infer source authenticity or approval from populated fields.
