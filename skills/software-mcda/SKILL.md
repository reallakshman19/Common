# Software MCDA skill

An independent, read-only decision-support skill. It requires neither the Workflow Progress Monitor nor GitHub, SMTP or ChatGPT Work.

## Workflow

1. Define the decision, time horizon, equivalent scope, competing engineering alternatives and mandatory requirements. Do not mistake a workflow stage (e.g. BuddyRunner 1a/1b/2) for an MCDA option.
2. Agree on 4–7 preferably independent criteria and weights summing to 1.0, before option scoring. Higher ratings always mean better results.
3. Specify rating anchors and collect auditable evidence for each criterion and option. See [references/scoring-rubric.md](references/scoring-rubric.md). Do not infer performance/security from a comment marker or incomplete snippet. Mark missing data UNKNOWN or NOT_EVALUATED; never silently assign a midpoint.
4. Validate mandatory requirements separately from preference scores. A failed hard requirement is ineligible; an unknown requirement is unresolved, not verified as passing.
5. Create the decision JSON following [assets/example-decision.json](assets/example-decision.json). Example data are explicitly ASSUMED, never an approved live project assessment.
6. Run from repository root:

    python3 skills/software-mcda/scripts/mcda.py skills/software-mcda/assets/example-decision.json --format markdown

   To test sensitivity and crossover:

    python3 skills/software-mcda/scripts/mcda.py skills/software-mcda/assets/example-decision.json --sensitivity cost=0.50 --break-even cost --format json

7. Report ranked eligible options and numerical contributions, tie/unresolved decisions, provenance, limitations, sensitivity and next experiments. MCDA is advice, never permission to implement, advance workflows, change scores or merge.
8. Run offline tests:

    python3 -m unittest discover -s skills/software-mcda/tests -v

## Separation and safety

- Engine: pure deterministic Python with no third-party packages, network calls, GitHub writes, scheduler or delivery channel.
- Project scoring configuration and evidence are owner-approved inputs, not generated by a monitor. Unattended integration must refuse unknown/assumed ratings for live recommendations.
- Workflow stage observations from PR #364 are SUBMITTED/UNVERIFIED or UNKNOWN, not independently verified engineering results. Do not promote them into scores or completion status.
- Respect repository AGENTS.md, Owner decisions, protected source/benchmark truth, PASS/FAIL/NOT_RUN status and merge authority.
- The optional workflow-intelligence adapter is separate; this skill must remain functional if that adapter is absent.
