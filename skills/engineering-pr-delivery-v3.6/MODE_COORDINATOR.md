# v3.6.1 Coordinator mode

**Selection:** An approved `relay/AIM/<WORK>.yaml` contains `mode: coordinator`, or
omits `mode` (the backward-compatible default). This is a mode of the
**same** v3.6 core, not a separate implementation or imported v3.5 engine.

## Actors and authority

The Owner retains intent, amendments, acceptance and protected decisions.
The current Team protocol v3.2 and CONTROL epoch determine the actual
TeamCoordinator, OwnerTeammember, any nominated Oracle, and work custody.
A role tag or NextMove is not a grant. The Oracle advises; it does not
dispatch, approve or merge. Independent verification must come from a
qualified non-doer on the exact candidate.

A merge may be performed by the designated Owner delegate only within a
current, recorded Owner grant and after the required independent review.
The coding agent must not self-review, self-approve, close or merge.

## Native core obligations

Use the selected label, matching approved plan and real task/child issues.
The existing O1–O5 lifecycle, dry-run defaults, explicit --apply/
--confirm-scope, owner-controlled acceptance, eight-line TASK_EVIDENCE,
terminal LOG, full tests and A01–A14 remain governing. The label's
`Writable lab:` directive is not a global write permission.

## Additional coordinator workflow

- Reconcile Owner intent, current control epoch, registry, authorized custody
  and the selected team's actual native evidence scheme before execution.
- For each finished work unit, post its native child issue evidence and A14
  self-check, then mirror the required team TASK EVIDENCE v2 / status to the
  authorized project evidence issue. Link sources and exact tested SHA.
- Use the approved role tag with the eight-character identifier for team
  evidence; preserve logs, logged sends, uncertainty, and NextMove authority.
- Have a non-doer check the frozen head and both full-suite test states;
  permit delegated merge only within the Owner's recorded authorization.
- The TeamCoordinator conducts cold successor routing; OwnerTeammember checks
  the 1b stage where the selected governed method requires it.

The v3.6.1 mechanical checkpoints C1–C18 (WP2) and scored SELF-CHECK v2
(WP3) will add checks to this workflow; they do not change canonical
task-evidence or LOG formats. See [MODE_STANDALONE.md](MODE_STANDALONE.md)
for the A01–A14 classification shared by both modes.
