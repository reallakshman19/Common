# Benchmark Revision Protocol

## Purpose

Use this when revising a bucket or comparing against a stronger existing bucket.

The goal is to improve pedagogical function, not to copy appearance or wording.

## Benchmark-before-revision steps

1. Inspect a strong existing bucket if available.
2. Compare pedagogical functions, not visual decoration.
3. Identify what is missing from the current bucket.
4. Preserve the current bucket's mathematical identity.
5. Do not copy wording, problems, layouts, diagrams, or visual composition.
6. Regenerate only after the gap analysis.
7. Run PDF preflight again after regeneration.

## Functional comparison checklist

```text
[ ] source trace is explicit
[ ] source integrity classification exists
[ ] one invariant drives the bucket
[ ] first-move recognition is operational
[ ] anchor is fully worked
[ ] support fades across later items
[ ] transfer changes reasoning, not just numbers
[ ] misconceptions include repair moves
[ ] checks include algebraic/structural/domain/reasonableness where relevant
[ ] citation labels are verified or downgraded
[ ] PDF preflight passes
```

## Do not copy rule

A benchmark may inspire:

- missing section types;
- quality gates;
- pedagogical sequence;
- density balance;
- citation discipline.

A benchmark must not be copied in:

- wording;
- exact problems;
- page composition;
- diagrams;
- titles/headings beyond generic functional labels.

## Revision report format

```text
Benchmark used:
What was missing:
What changed:
What was preserved:
What was not copied:
Preflight result:
```
