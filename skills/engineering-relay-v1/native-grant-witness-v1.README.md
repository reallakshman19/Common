# R1-B.2b — dual native Owner-comment source witness; NOT human Owner authorization

[Root #787](https://github.com/reallaksh19/Common/issues/787) → [R1-B policy #792](https://github.com/reallaksh19/Common/issues/792) → [bounded task #808](https://github.com/reallaksh19/Common/issues/808). Implemented after owner-directed integration of real R1-A/B/C code into main at `022a911aa0d27556b72cff61a6bcae9bd369aa50`.

`readNativeGrantWitness(input)` uses the **actual merged** `readNativeOwnerComment()` twice, for a distinct alleged *earlier grant* comment and *later decision* comment. Both must be in the governed repository, separately pinned to SHA256, have exact provider issuer/issue/HTML/REST URL bindings and share a native `OWNER` issuer. The grant must predate the decision, including the **last native edit time**, so a later edited alleged grant cannot masquerade as a prior unchanged one. The output is a minimal reproducible source witness with current observation time but deliberately excludes the raw body (privacy). It does NOT parse or conclude that either comment is an actual Owner decision or genuine prior grant.

**Important conceptual limitation:** GitHub `author_association=OWNER` proves a repository account, not unforgeable personal intent. Agents writing under the Owner's account may author genuine native comments. There is not yet an independently authenticated human Owner authorization-root revision in this fresh programme. A true trust root must be *explicitly granted and anchored by the Owner*, independent of the candidate comment; the grant cannot self-certify. Thus even when both live native comments are observed, the function ALWAYS returns `authorization_granted:false`, `owner_grant_authenticated:false`, `human_owner_consent_verified:false`, `independently_accepted:false`, `live_writer_enabled:false`. These outputs are not GitHub writer permissions.
