# Golden cases: decisions and their limits

These are synthetic reference cases, not completed product reviews. Use raw inputs
under `raw/` for application; withhold this index and expected outcomes when testing
unaided discovery. Shared workspace access is not enforced by the skill.

| Case | Situation | Defensible behavior |
|---|---|---|
| G01 Sound work | `raw/lesson.md` meets its declared learning task. | Independently work through it; an empty finding set is valid within that scope. Do not invent a defect or claim a classroom trial. |
| G02 Green tests, wrong rule | `raw/rate.py`, `raw/test_rate.py` and `raw/owner.md`. | Author tests can pass while a threshold applies to the wrong base. Derive expected behavior from the Owner rule and retain a reproducible counterexample. |
| G03 Missing evidence plus defect | Source shows a defect but the target browser/fixture is unavailable. | Keep the source finding and runtime NOT_RUN separately; continue unaffected checks. Return attempted action, restriction, affected scope and next route. |
| G04 Stale candidate | `records/current.json` changes one candidate revision. | Preserve `result.json` attached to its original candidate. Determine affected claims before reusing evidence; no automatic project invalidation. |
| G05 Self-review | Candidate author performs a fresh check. | Keep useful evidence with SELF_REVIEW and exposed-context limits; do not claim independent P2 or wait for another participant to begin. |
| G06 Narrow custody task | `raw/custody.json` supplies file names and expected hashes. | Hash actual bytes, compare values, reject an altered disposable copy; do not infer semantic or whole-product correctness. |
| G07 Copied benchmark | Generated questions were derived from the comparison benchmark. | Establish provenance first. A faithful match supports reproduction but cannot alone establish unseen transfer. |
| G08 Correct components, failed journey | Unit checks pass while the original route cannot finish. | Preserve unit evidence; keep the integrated claim unestablished and select a meaningful journey observation. |
| G09 Long mixed project | Several local evidence tasks plus one coupled state/model decision. | Split durable mechanical evidence only where useful; retain coupled judgment/integration with an available capable participant, without a fixed role roster. |
| G10 Shared wrong oracle | Author and reviewer compute consistently from the same unjustified unit/model assumption. | Trace the original givens and independently justify the model; replay agreement does not establish it. Keep useful execution evidence and the unresolved premise separate. |

`records/` provides a complete optional case/result pair with actual small source
and receipt files, plus caller-supplied freshness observations. The receipt is a
synthetic illustration, not a hosted execution receipt. `tests/` mutates copies
to exercise stale binding, self-review mislabelling, partial evidence and byte/path
failure cases. The helper's consistent result cannot establish substantive truth.

For a real review, replace all synthetic inputs and locally observed evidence.
For FEA or other consequential model questions, a guided arithmetic operation
cannot substitute for justified model selection and actual project criteria.

See [actual prototype applications](applications/assessment.md) for issued raw
tasks, untouched native returns, execution witnesses, parent verification and the
limits of the observed results. These are local synthetic applications, not the
planned real LFEA pilot.
