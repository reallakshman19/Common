# Optional adapters between independent modules

Use direct review when no integration helps. Select adapters from project needs,
available participants and existing records. These are file/reference mappings,
not Python imports, automatic dispatch or required services. No sibling skill
installation is needed. Never silently replace the authoritative task definition.

| Adapter | Bring in | Return/preserve |
|---|---|---|
| Task Decomposer | Selected map/task identity, revision/digest, original sources, required understanding, dependencies, protected constraints and acceptance contrast | Review Case binding and evidence for that boundary; propose visible meaning changes to the available lead. Keep parent integration/deferred work. |
| Nudge Designer | Review Case or native assignment, task-specific capability observations, accessible inputs, tools and return channel | GUIDED or OPEN brief, exact issued binding and native report. ND's execution COMPLETE is not review PASS. |
| Project policy/profile | Exact selected protocol/profile revision, applicable criteria, authority and project amendments | Native criterion results and findings referenced without translating away their semantics. Do not create a competing criterion catalog. |
| Tracker/native reporting | System-of-record task/move ID, issued snapshot, authorized response channel | Explicit assignment-to-tracker mapping, preserved native report, reply link and artifact references. |

## Task Decomposer mapping

Read the externally selected version's contract first. Store map ID, task ID,
revision, locator and digest in optional `bindings`; copy required meaning into
the accessible case or reference pack. A canonical map digest and the source
file-byte hash are different identities. Do not reinterpret KEEP/SPLIT/MERGE or
other planning labels as review qualification. Use its impact output as advisory
dependency information, not automatic invalidation or an execution permit.

## Nudge Designer mapping

Select an actual review/evidence assignment before rendering an audience view.
A reviewer view of a product task does not by itself create a review task. Keep
the selected version's permitted audience and support vocabulary; this skill's
DIRECT support corresponds to an OPEN method when the selected ND contract does.
Oracle is a responsibility, not a new ND audience enum. Carry both the ND-issued
binding and this review run/candidate binding if structured records are used.
Use native report preservation; schema intake does not establish claim truth.

## Policy mapping

For an engineering project selecting Common Reviewer Protocol, read its pinned
effective Common/project profile and native schema. Preserve CR-01 through CR-10,
applicability, waivers, findings and native result values there. Reference that
report from the Review Result; this module's scoped verdict is a separate summary.
Do not rename a same-principal SELF_REVIEW as a distinct REVIEWER, infer principal
authentication from a field, or waive project authority through adapter omission.
For study material, research or other domains, select relevant criteria instead
of automatically importing engineering release policy.

## Transport and tracker identity

Distinguish task ID, candidate ID, review-run ID, assignment ID and tracker move
ID. If a tracker requires `ACK <move-id>`, use that issued ID and retain an explicit
mapping to the assignment/run. Do not hand-change sealed content or assume a
tracker accepted a designed packet verbatim. Inspect the actual app/import contract
before promising native integration. No live NextNudge adapter is implemented here.

Hash original artifact bytes separately from a posted transport copy. In a working
view, a leading BOM may be tolerated when matching ACK; retain original bytes and
report garbled text/duplicate count lines. Never silently normalize a file before
checking its digest. The helpers do not fetch URLs, watch channels or send messages.
