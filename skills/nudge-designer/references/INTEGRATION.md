# Integration without hidden coupling

Nudge Designer works alone with a human and agent. It authors draft instructions.
It does not invoke another skill by mentioning it, authenticate an Owner,
dispatch a worker or merge code.

## BuddyRunner and recovery/onboarding

BuddyRunner can use the two objects as durable reconstruction outputs. Keep its
actual recovery/onboarding continuation choice and authorization. Onboarding can
wait for the next task where the Owner requested that behavior; already authorized
recovery continuation should act within its scope. Add no per-nudge approval gate.

Blocked continuation reports the attempted action, observed restriction, affected
scope and next feasible action. Publishing a reconstruction is not executing a
repair. The Designer adds source/dependency structure without replacing those
evidence and continuation responsibilities.

## Thinking, handover and coding delivery

Keep each independently selected. `protocols.thinking` and `protocols.delivery`
record selections, not imports. A project can select Handover Master for a
reasoning operation, BuddyRunner for succession and engineering PR delivery for
coding. Mentioning engineering-pr-delivery-v3.6 must not silently invoke its
legacy handover/thinking default.

This package changes none of those skills or project backup/review requirements.
Use actual authorization and applicable instructions; a plan field cannot
manufacture missing implementation rights.

## NextNudge workbench

Owner-supplied reference:
https://nextnudge-workbench.lushflame4.chatgpt.site/nextnudge/

Owner amendment NN-R2:
https://github.com/reallakshman19/CoordinatorLandingpage/issues/97#issuecomment-6247743663

The observed workbench uses Nudge Protocol v2 and manual Owner controls. This
records the design boundary; it does not requalify every current deployment.
The Designer's `type` vocabulary matches the observed labels: `new_requirement`,
`ground`, `next_step`, `course_correction`. Those labels alone do not make the
objects native workbench imports. The `nextnudge-manual` adapter now prepares a
manual-copy draft packet. It is not a native import object, automatic send or UI
change. GitHub, BuddyRunner checkpoint and selected-delivery adapters similarly
prepare material under the existing authority and native reporting conventions.
See [adapter contracts](ADAPTERS.md) for role views and native-return intake.

For a later separately authorized adapter:

- Inspect the actual version and import contract before coding.
- Convert drafts into editable, visible steps with source/plan identity; retain
  remaining, conditional and independently eligible work.
- Keep every step visible; dependencies explain rather than sequentially lock.
- Preserve manual Copy and Mark sent. Do not send work or write to GitHub merely
  because the Designer produced a plan.
- Freeze sent instruction snapshots; use visible correction proposals and review
  rather than rewriting history.
- Keep local Owner acceptance separate from external protocol verification.
- Preserve source conditions, authority and existing reporting/grounding semantics.

Pilot the blueprint and objects first. Add UI controls after actual use shows
which decisions need support; field completeness is not the success metric.
