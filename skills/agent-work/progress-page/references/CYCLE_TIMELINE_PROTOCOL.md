# Cycle now via Timeline — source-first operational protocol

**Optional visibility overlay, not a coordination/engineering mode.** The selected OTM/Oracle/direct-Owner mode, native engineering rules and [canonical Oracle Cycle](../../../../oracle-cycles/PROTOCOL.md) remain controlling. A badge, role or displayed chat identity never activates a Cycle, assigns an agent, verifies independent review or grants acceptance.

## One source; multiple read-only views
1. **Work from the assigned native source.** Coder/IR/Oracle records original work once in the task issue/PR/test/authorized [artifact relay](../../ARTIFACT_RELAY.md), under [START_HERE](../../START_HERE.md). No periodic Timeline heartbeat, duplicate agent report or special JSON submission should be required if the original evidence exists.
2. **Observe existing evidence.** The read-only Timeline uses original URL, revision/head, WBS/card identity and actual source timestamp. Missing, ambiguous, unavailable or partial observations stay UNKNOWN/UNRESOLVED. Current `INFO-Auto generated` is derived from existing audited Page changes; *automatic discovery of all native/chat events is not yet implemented*. [Common intake #564](https://github.com/reallakshman19/Common/issues/564) is only a public-safe optional fallback for explicit live-card events until a source-first observer is built.
3. **Session identity.** A participating agent knows Project Name, full self chat ID, interacting chat's full ID (or NO_DIRECT_PEER), and CODER/ORACLE/REVIEWER_IR role. Public display aliases do not authenticate chat identity, roles, independent review or permissions. No repeated registration per badge.
4. **Two event semantics.** `ACTION` is one outstanding owed step (including a specific `NEEDS_OWNER` question if applicable). A source-linked `INFO/HANDED_OFF` can close the communication Action; it cannot close the separate IR technical-review Action or assert PASS. Keep the original event, exact thread, WBS, card, actor, source and surviving next action. Silence is UNKNOWN, not DONE.
5. **Smart Badge identifiers.** Reuse the same source-derived `project/type/key` identifiers in Timeline, Agent Start, writer grounding brief and Oracle continuity: AIM (Owner aim), ROADMAP (recorded milestone), WBS (exact milestone), PLAN (audited plan event), FIXTURE (audited fixture-list event; not verified bytes), ORACLE_CONTINUITY (pre-existing Oracle-specific record). Missing source is SOURCE_UNAVAILABLE, not a free-form second tag catalog.
6. **One authorized reconciliation.** Only the incumbent Oracle updates canonical Cycle under its authority. Only the designated Page writer may publish Page WBS/cards/fixture/roadmap changes through checked `pp_propose → pp_batch` and audited Page PR under [mode rules](MODES.md). A Timeline badge, fixture link or copied text is a proposal to inspect, not authority to write.

**Resume:** Agent starts at its *actual assignment* and inspects deltas; no mandatory Test page. Owner, agent or reviewer may optionally demonstrate UI in the [Test page](TEST_PAGE_PROTOCOL.md), which has no production side effects. Oracle/successor must verify current canonical Cycle, native assignments, original evidence and unresolved gates.

**Production first. Evidence once. No duplicate reporting.**
