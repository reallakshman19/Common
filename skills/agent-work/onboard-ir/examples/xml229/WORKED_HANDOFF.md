# OBIR-G01 — worked historical handoff and an anti-oracle-continuity lesson

**Purpose:** demonstrate how to hand a complex engineering review to an unbriefed participant without making them endorse the preceding developer's theory. Historical example from 2026-11-02; not live current assignment or source-verification claim.

## Historical situation (source-backed pointers; read after Stage 1)

- Public repository: https://github.com/reallakshman19/3D_Converters
- Baseline main reviewed: immutable commit https://github.com/reallakshman19/3D_Converters/commit/5c39dd7bdbb7f2f63a686823b72bdb81909d52af
- Original design/WBS: https://github.com/reallakshman19/3D_Converters/issues/391
- Candidate proposed stack: draft PRs #392–#399, stacked, not merged to main at handoff time.
- Original external evidence: Owner reported **21 mandatory row-level position ambiguities** in a V6 source. Original private XML, JSON, offset/config, and exact Final/output were **not available to this reviewer-handoff author**.
- Public synthetic and selected benchmark tests showed partial functions; some actual native CII tests used distinct positive source node IDs rather than the original ambiguous rows. This distinction must be preserved.

## Sender's first attempt: useful but not an independent verdict

An existing development assistant initially focused on graph-vertex indexing, multi-member nodal restraint projection, pre-Final materialization, an opt-in node-contraction audit and independent Python replay. It produced several green PR-head tests. The assistant then reviewed its own approach and found that **original source graph authority was still unproven** and the actual 21 private claims were unreplayed. That is substantive **SELF_REVIEW**, not a separate independent IR.

The error would have been to teach a new "independent" reviewer that those proposed graph rules and candidate fixes are the expected answer. Instead the review assignment divided evidence:

**Stage 1 (cold):** original Owner outcome, immutable main, actual baseline module paths, original-source custody and failure fact only. Require reviewer to infer identities, graph rules and an observable wrong case. Return this to the existing native review issue before candidate disclosure.

**Stage 2:** provide issue #391, proposed PR stack, actual changed files, CI logs and implementation claims. Require compare with Stage-1 model, source-line findings, surviving wrong cases and native CII output. Accept corrections to Stage-1 when authentic source warrants them; label prior exposure.

**Reconcile:** return one source-backed issue/WBS finding set for Oracle/Owner to accept, correct or investigate. No auto-merge, no second WBS, no claimed CII release and no fake ACK.

## Why the earlier approach was insufficiently continuous

- Green tests tracked code **behavior**, but not always the authoritative **expected engineering topology**.
- A proposed canonical positive-node mapping could create native **self-edges** if consecutive identical-XYZ rows were not actually contracted.
- Read-only contraction safeguards could replace "ambiguous support" with a different HOLD without achieving output.
- The real private Owner source was missing; no complete claim-by-claim source graph oracle existed.
- Later agents could inherit an "all green" summary without the failed hypothesis, source SHAs, alternative explanation or exact runtime boundary.

## Golden methodology verdict (NOT a real V6 product verdict)

**CONDITIONAL / NO PRODUCTION RELEASE:** Preserve useful source-to-physical-vertex and multi-member model work, but freeze further production features until original 21 cases can be classified from authentic source and one end-to-end original source → pre-Final → accepted mass → actual CII has independent graph, restraint and mass verification.

An alternative independently source-supported verdict is welcome. This golden judges the **review handoff and evidence boundaries**, not any engineer's final topology interpretation or user authorization.

## Reuse in a different domain

Replace XML graph / CII with any source-to-product pipeline (finance, documents, learning, web application). Keep the same essentials: original meaning before producer conclusion, exact bytes and current candidate, an adversarial counterexample, a distinct recipient receipt, source-grounded dissent, one governing WBS and a decision trail that future agents can test again.

**No protected Owner file is embedded; no private-source replay or independent third-party review is claimed.**
