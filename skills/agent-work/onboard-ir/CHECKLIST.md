# OnBoard IR field checklist — use only items relevant to this review

This is an **inspection aid**, not a new WBS, acceptance gate, admission score or demand to repeat completed mentoring. Mark UNCLEAR/NOT_RUN where evidence is missing and scope the dependent claim.

## Before Stage 1: legitimate source grounding

- [ ] Existing Owner aim, one WBS task/step, review scope and native return identified (else UNKNOWN).
- [ ] Real recipient, actual role and read-only or preexisting permission established (not inferred from chat name).
- [ ] Baseline exact commit, relevant original source/config and candidate *as separate objects* identified.
- [ ] Reviewer independently accessed actual permitted bytes/refs, or recorded NOT_RECEIVED and affected scope.
- [ ] Original requirements, domain constraints and known safety HOLDs available; producer solution conclusions not provided as expected answers.
- [ ] Authorship, shared principal, prior exposure, shared upstream expected behavior recorded honestly.

## Stage 1 baseline

- [ ] One original source value traced to output meaning and a wrong case in reviewer words.
- [ ] Independent expected graph/member/value or product rule stated with actual source and uncertainty.
- [ ] At least one surviving-error hypothesis and discriminating test.
- [ ] Stage-1 conclusions returned to the existing native task **before** opening producer proposal/golden; citation/revision captured.
- [ ] Unavailable original/fixture documented and dependent production claim NOT_RUN.

## Stage 2 candidate

- [ ] Exact PR head and actual changed modules read; not just prose, green CI or local stale copy.
- [ ] Review of entrypoint, flags, native output and legacy/unaffected route.
- [ ] Source-member counts, ownership, geometry, negative cases and output checked to the extent relevant.
- [ ] At least one seeded defect rejected **at intended checker boundary**, or NOT_RUN honestly recorded.
- [ ] Producer assertions classified SUPPORTED / CONTRADICTED / UNKNOWN, with surviving wrong case.
- [ ] Reviewer contributions to candidate disclosed; affected scope cannot be self-approved as independent.

## Return and continuity

- [ ] Findings bind source hash, candidate commit, inputs/config, executed methods, witnesses and first-divergence explanation.
- [ ] Oracle/Owner reconciles each material finding without replacing reviewer's original verdict.
- [ ] Current WBS and original native issue/PR are the record; no parallel matrix promoted to governing WBS.
- [ ] A change in source, branch head, config, reviewer or authority invalidates only affected claims; old return retained historically.
- [ ] Any private artifacts use authorized custody; transfer, receipt, native execution and approval are separately evidenced.
- [ ] Next actor, bounded action, required original evidence and exact return identified; HOLDs remain scoped.
- [ ] For an established reviewer/Oracle, changed-only continuation—not another onboarding/quiz.

**Falsifier:** a new reviewer receives both Stage-1 prompt and the golden expected solution in the initial packet. OnBoard IR **fails the blind-baseline independence claim**, even if the subsequent report is detailed and technically correct. Reclassify exposure rather than rewriting history.
