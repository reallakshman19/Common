# Agent OnBoard bridge — source-rich but solution-neutral IR briefing

Use with the existing [Agent OnBoard](../nudge-designer/assets/agent-onboard/README.md) and [Initial Mentoring](../initial-mentoring/SKILL.md). This bridge provides a specialized **reviewer-facing one-WBS task brief**, not four new obligatory documents.

## Sender: Oracle/Owner preparing a cold IR

**Give in the first message:** exact Owner outcome; one live WBS task and native review return; selected coordination/engineering protocol; real recipient identity/permissions; original user input, config and domain meaning with immutable ref and privacy; relevant baseline commit; constraints/no-go actions; exact requested output; source of recognized HOLDs. Distinguish present facts from unresolved hypotheses.

**Hold back until Stage-1 return:** the author's proposed solution and diagrams, PR stack claims, producer CI PASS narratives, worked answer/golden and any author judgment of "correct owner", "correct graph" or expected native result. Do not withhold essential original safety constraints or source data needed to understand the problem. If reviewer already saw producer material, disclose exposure and continue as scoped assessment, not blind-baseline claim.

**Delivery:** Link actual permitted bytes via public-safe immutable Common relay **or** Owner-authorized private Drive Handoffs; receiver separately verifies access/digest where relevant. Neither a chat upload receipt nor sandbox URI is a confirmed reviewer transfer. Never publish private original coordinates or model names in public golden files.

## Receiver: own-words source walkthrough, not a quiz

The reviewer should demonstrate three properties through its work:

1. **Meaning:** Why does the user need this artifact or conversion, and which wrong engineering output is dangerous?
2. **Hard architecture:** Trace an original record through a real source transformation and name a plausible competing interpretation with discriminating evidence.
3. **Connected action:** Which existing task/WBS slice is under review, what exactly must be returned, and which downstream decision depends on it?

If unable to trace a crucial value, say which exact source/custody gap blocks which conclusion. Continue safe read-only checks. Do not convert a missing source into a guessed design, another Owner questionnaire or new review protocol.

## Two-way feedback matters

The reviewer is encouraged to challenge the **sender's baseline expectation**, not just the implementation. When it does, Oracle/Owner responds ACCEPT / CORRECT / INVESTIGATE with actual source evidence and changed next action; never mark a dissenting IR "failed onboarding" merely for disagreement.

If review points to a need for code repair, hand findings to the existing authorized builder. An IR who is separately approved to contribute must explicitly change role and surrender independence over affected scope. Writer permissions are not inherited from the review brief.

## Replacements and continuing agents

A new reviewer is a new recipient/assignment generation even if task ID stays the same. Independently verify its source/candidate receipt. Preserve previous reviewer's Stage-1 model as provenance, not as a forced answer. An **already grounded** returning reviewer receives only changed source/head/role/custody and required new falsifier; no re-onboarding.

**Minimum copy-ready brief:** [IR assignment](templates/IR_ASSIGNMENT.md); [cold source prompt](templates/STAGE1_COLD_PROMPT.md); [candidate prompt](templates/STAGE2_SOLUTION_PROMPT.md). Return **once** to the existing assigned native task and permit Oracle/Owner to reconcile.
