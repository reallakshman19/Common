# Agent OnBoard — ORACLE → AGENT: one WBS-level continuity prompt

**START HERE: [ONE ORACLE-ISSUED WBS PROMPT](AGENT_ONBOARD_PROMPT.md).** The recipient inherits exactly **one WBS task**: parent Owner outcome, upstream/downstream dependency, source contract, current task/assignment generation, predecessor evidence, exact PR head, authorized files, source custody, test/negative case, and one native return. This is not a project-wide Oracle succession prompt. The Oracle already read [project continuity](../oracle-onboard/ORACLE_ONBOARD_PROMPT.md) and distills only **relevant** context here. The four documents below are **optional reference/scaffold material for missing source explanations**, not tasks to copy, fill, re-author or formally approve before the agent acts. An established agent gets changed-context delta only.


**For a genuinely new or replacement assigned builder, specialist or independent reviewer.** This is an extension of the existing [Oracle OnBoard guidance](../../references/ORACLE_ONBOARD.md) and [seven-element assignment](../prompts/assignment.md), **not a new protocol, form, reviewer role, test, dispatch system or admission gate**. An existing grounded agent uses a **delta-only continuation** and must not rerun onboarding.

The Owner selected the four immutable [3DC golden Oracle handover artifacts](https://github.com/reallakshman19/Common/tree/bf02e54e1b453c3206ae366de7d65f41c94ab0d4/relay/AGENT_WORK/3DC-XML-CII/oracle-continuity-20261025/payload) as a *quality benchmark*. Use their explanatory depth, original-source discipline, concrete wrong cases and honest evidence boundaries. **Do not import their engineering facts or authority.**

The authorized coordinator/Oracle fills the following **from this recipient's actual project**, or links an existing source-grounded equivalent:

1. [CONCEPT_NOTE.md](CONCEPT_NOTE.md) — exact Owner WHY, user journey, current versus desired capability.
2. [ARCHITECTURE_COMPLEX_LOGIC.md](ARCHITECTURE_COMPLEX_LOGIC.md) — causal input→candidate→result trace, difficult source meaning, identity and state invariants.
3. [ARCHITECTURE_DECISIONS_AND_CHALLENGES.md](ARCHITECTURE_DECISIONS_AND_CHALLENGES.md) — chosen/rejected alternatives, plausible surviving errors and discriminating tests.
4. [AGENT_HANDOVER.md](AGENT_HANDOVER.md) — exact assigned slice, scope/permissions, candidate, file transport, native return, one executable NOW and next dependency.

[AGENT_ONBOARD_PROMPT.md](AGENT_ONBOARD_PROMPT.md) is the complete copy-ready instruction for the *assigned* agent. The four Markdown files are **fillable examples, not evidence that a particular project's sources were inspected**. Replace each `{{...}}` with a verified source or `UNKNOWN / NOT_RUN / NOT_TRANSFERRED`; drop irrelevant sections. A project with trustworthy existing Project Home, architecture ADR and native task evidence **links those** instead of cloning four files.

## One real task; no endless handoff loop

The Oracle/OTM or direct Owner pre-resolves coordination mode, native protocol, recipient/role, task identity, source/candidate/fixture access, permissions, exact return and the first useful action. Apply [Initial Mentoring](../../../initial-mentoring/SKILL.md)'s adaptive themes **within the first source/task walkthrough**: the agent's own explanation of parent WHY, architecture rationale and a real task-relevant source trace/negative observation, and next result with actual upstream/current evidence, owners and downstream consumer. Do this before consequential plans/briefs; combine themes as useful without a question quota, separate ACK, essay, exam, form or approval. The recipient continues the **same assigned task**, without redesigning the project or creating prerequisites/reporting modes. A preparer who does not understand a material source rule **reads the source and corrects the explanation**; unavailable originals/checks stay `NOT_READ`/`NOT_RUN` and narrow only dependent claims.

For a **reviewer**, supply task-neutral original requirements, candidate and permitted fixtures; withhold producer answers, diagnoses and seeded expected test results. The reviewer derives expectations from originals and discloses authorship/prior exposure. A fresh chat ID does not authenticate non-author independence.

**File delivery priority for every material artifact:** Option **1** immutable **public-safe Common relay**; Option **2** authorized **Google Drive Handoffs** for protected files or when 1 is unusable. One of 1 or 2 is required to call a cross-agent transfer complete, with an existing task-scoped sanitized Common receipt. A `sandbox:` or `/mnt/data` link is `LOCAL_ONLY / NOT_TRANSFERRED`, not delivery. Recipient confirms actual bytes/digest independently where identity matters. Follow [Artifact Relay](../../../ARTIFACT_RELAY.md).

**PR title and Chat ID:** Use [native title/traffic hygiene](../../references/TITLE_AND_TRAFFIC_HYGIENE.md). For a human-owned PR under permissive native naming, prefer `[<TASK-ID>][<ROLE>:<verified CHAT-ID8>] <specific result>`; if the native owner/projects enforce a title pattern or generator, keep it and put Chat ID in the issue/PR body. For v3.5 DELP-managed **issue** titles, no human edits of traffic light, P/E/D, or status; the projector owns them. Never guess an ID8, treat it as authenticated identity, or fake PR green.

**Execution authority comes only from the actual native assignment/Owner**, not this template or the four knowledge documents. A reviewer cannot edit the producer PR merely because the packet contains write instructions; a successor builder cannot overlap the predecessor's write surface without native isolation and new assignment binding. Not every project uses a `CURRENT.json` Cycle, Progress Page or v3.6. Nothing here activates them.

## Usage

- **New recipient:** fill once or link established project equivalents, send the concise [prompt](AGENT_ONBOARD_PROMPT.md) with actual source/issue/reply locations and let the agent do the bounded task.
- **Existing grounded agent:** reuse that participant's own demonstrated understanding when its source/candidate basis is unchanged; send only relevant source/task/head/contrary-evidence deltas.
- **Replacement agent:** retain task ID, mark new assignment generation and old pending returns **from actual native state**; isolate writer access before overlapping work.
- **Independent reviewer:** use its existing [review protocol](../../../independent-review/SKILL.md), declare author/account/expectation exposure, retrieve exact candidate and run a meaningful opposite case.
- **If an essential source cannot be accessed:** name the exact missing file/action and continue authorized disjoint work; escalate to Owner only what Oracle cannot resolve or what Owner genuinely reserved.

This reusable template does **not** claim that a real agent read files, executed a browser, published a PR, received private bytes or produced an independent verdict.
