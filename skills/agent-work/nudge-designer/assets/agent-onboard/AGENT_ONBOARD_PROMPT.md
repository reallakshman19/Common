# Agent OnBoard — ONE Oracle-issued WBS-level continuity prompt

**UNIT OF CONTINUITY: ONE WBS TASK. SENDER: PROJECT ORACLE → ASSIGNED AGENT.** Use for a new/replacement builder, source specialist or independent reviewer on a *specific native WBS responsibility*. Unlike the **Owner → Oracle project-continuity prompt**, this must **not** assign project-wide coordination, restage the whole project, require four copied golden documents, create a new Cycle or make an agent design the task.

The Oracle already owns the broader project model. It extracts the **relevant** Owner WHY, difficult source semantics, decisions and working history into this ONE executable instruction. Existing WBS issue, parent/roadmap, task PR, native evidence, local handover and relay are reused as the authority; the optional [four knowledge scaffolds](README.md) are for filling a *missing* project/task-specific explanation, not mandatory recipient work.

## Why the two OnBoards are different

- **Owner → Oracle** [one project continuity prompt](../oracle-onboard/ORACLE_ONBOARD_PROMPT.md): *entire* Owner product intent, architecture and decisions, **all** WBS states, actors, reviews, precedence, project next priorities and possible Oracle cutover.
- **Oracle → Agent** (this prompt): **one existing WBS responsibility**, its inherited project context, exact predecessor/branch/fixture/evidence, bounded source contract, local wrong case and native return.

**No new approval gate or added four-document exam exists.** A complete WBS task return should let a replacement agent continue that WBS from the existing issue and PR alone. The Oracle remains the project's single owner of coordination continuity. This difference is not an added exam, a second planning track, a new identity registry or automatic authorization.
