# Oracle OnBoard — ONE Owner-issued, project-wide continuity prompt

**UNIT OF CONTINUITY: THE WHOLE PROJECT. SENDER: OWNER → ORACLE.** This is the one prompt the Owner pastes into the intended Oracle chat. It hands over the project model, **all WBS workstreams and actors**, and the authority frontier; it does **not** assign an individual coder leaf. Unlike Agent OnBoard, it must not turn the whole project's four knowledge classes into a separate questionnaire or require a new file per WBS.

The Owner provides a project/Owner AIM link (and existing Home/Cycle when known). The Oracle itself retrieves current sources and resolves accessible inconsistencies. Project-level `CONCEPT_NOTE`, `ARCHITECTURE_COMPLEX_LOGIC`, `ARCHITECTURE_DECISIONS_AND_CHALLENGES`, and `ORACLE_HANDOVER` or **existing substantive equivalents** are **source knowledge**. If absent, the Oracle creates the smallest source-grounded explanation within its authority, not a compulsory four-file admission gate. See [project knowledge examples](README.md) and [actual Oracle succession protocol](../../../oracle-standalone/references/ORACLE_HANDOVER_PROTOCOL.md).

## Ownership separation and actual use

The Owner sends **this single project-continuity instruction** once when appointing/orienting an Oracle; it is not a new Cycle, command server, mandatory exam or document-production task. The Oracle independently reads existing knowledge and creates **targeted WBS-level Agent OnBoard instructions** [here](../agent-onboard/AGENT_ONBOARD_PROMPT.md) only as needed. An incumbent Oracle already grounded in the project uses **delta-only continuation**, not this entire cold-start packet.

**Oracle handover invariant:** knowledge prepared ≠ successor accepted ≠ control cutover; all ongoing agent assignments, real Writer rights, exact candidate reviews, original-source custody and Progress Page publication status survive unchanged until explicitly and verifiably reconciled.
