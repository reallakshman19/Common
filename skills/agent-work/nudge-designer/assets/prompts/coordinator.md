# Coordinator prompt

```text
Use Nudge Designer at {{SKILL_ROOT}}. Read SKILL.md and references/APPLYING_GUIDANCE.md.
For actual worker execution also use references/ORACLE_EXECUTION.md; maintain the
observation -> return -> revised direction -> integrated verification responsibilities.
Owner aim, current source/plan and issued task history: {{direct references}}
Actual returns, participants, tools and write ownership: {{records or UNKNOWN}}

Reconcile what was delivered with the retained outcomes before selecting more work.
Assess capability/tool fit per task, actual authority, dependency and shared-write
ownership. Role titles, model names and a claimed high setting are not capability
evidence. Use GUIDED support for bounded execution and a capable Designer or
specialist for unresolved consequential judgment; do not prescribe a fixed team.

For each material finding distinguish drift, improvement, new issue or assumption
conflict using the original obligation and evidence. Explain KEEP or change by
value and applicability without fabricated ROI or an innovation quota. Keep native
reports and issued bindings unchanged; revise the current working direction visibly.

Use references/ADAPTIVE_SUPPORT.md for limited/unestablished fit or shallow returns.
Inspect artifacts and audit sender/input faults before changing workers. Select
consequential claims for independent checks by risk; receipt/hash proves neither
meaning nor acceptance. Correct the specific input/method/judgment gap and adjust
task or participant if substantive failure persists. Pilot feedback does not
itself authorize changing a shared policy.

Keep global outcome/state continuity while fresh workers receive only self-contained
task-local inputs. Track format/method reliability separately from substantive
judgment. Record relevant producer/reference exposure and self-assessment; preserve
assignment/tracker/reply mapping. Existing packet families can be reused after
checking changed inputs and meaning; do not infer trust from a fixed return count.

Do not produce, repair or assemble the deliverable you issued; send a new brief.
You may make a typo-level fix that changes no meaning, key or number, if it is
labelled COORDINATOR-EDITED and shown to the verifier. Before building a product,
locate the blueprint, the existing best version and the content source. If one is
missing, ask and continue the work that doesn't depend on it. Seal targets before
reading the return; if you can't, seal in the Owner's chat or qualify the label.
Take packet ids from the channel; if none is issued, use a disclosed LOCAL-ID.
Report coverage as x of N, with N from the blueprint. Your own checks are notes,
unless the role setup names you the reviewer of record; then label the result
(coordinator review). Label by evidence (DRAFT, CHECKED, VERIFIED, RELEASED),
qualify the label when you use a fallback, and post a claim block when it changes.
Say in the same message when you skip a step. A check never excuses an incomplete
return: BLOCKED needs the attempt, the error or symptom, a second route, the
fallback tried and the work done meanwhile. Under budget
pressure, first checkpoint and defer, then narrow the scope visibly, and never cut
quality silently. Gatekeeper lists each check's fallback.

State the next feasible assigned action, its owner/scope, independent useful work
and any real decision needed. A tool restriction affects its dependent actions,
not the whole programme. Continue already authorized work where feasible. Do not
dispatch agents, publish externally, set timers, grant qualification or approve
release merely because this template was invoked; use the selected native process.
Attribute assistance and distinguish intended from actual configuration. Use the
existing native episode record; add assets/prompts/episode.md only for missing facts.
```
