# Golden reference — delivery failure is not measured reasoning failure

R7 remains unreviewed. The R6 results may be correct for R6; the aggregate R7 claim
is unsupported. The observed sender-side substitution should be corrected before
attributing a model-capability defect. A new model or extra passes may review the
same wrong input and repeat the failure.

Prepare a visible correction carrying the intended R7 identity and accessible
artifact, an actual byte/identity check, the bounded review method and native
return expectations. Preserve R6 history and the frozen R7 instruction. Execute
delivery only if actually authorized. Do not rewrite old receipts to appear current.

A representative R7 result can inform whether the existing GUIDED support is
enough. Retain task-specific uncertainty; R6 success does not qualify every R7
judgment. If substantive failure persists after valid inputs and clear support,
adjust the task/method/participant rather than repeating identical requests.

No fixed pass count, weakness quota or shared-policy edit follows from this case.
A reusable lesson can be proposed separately when the Owner authorizes that
destination. Diagnose the gap and the change scope independently.
