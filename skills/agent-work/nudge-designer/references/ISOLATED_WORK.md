## Select isolation for a reason

Give a fresh narrower worker one coherent deliverable when its inputs, necessary
understanding and acceptance evidence can travel together. Keep the WHY, source
identity, established decisions, relevant constraints and open judgments in the
issued brief. Oracle/coordinator retains the wider outcome, dependencies and
integration evidence. A fresh session must not depend on remembering earlier chat.

Choose among these arrangements; none is a universal phase or default agent count:

| Arrangement | Useful when | Important limit |
|---|---|---|
| Fresh task-local worker | A bounded count, observation, comparison or implementation has explicit inputs and a usable oracle | Context isolation does not establish skill or evaluator independence |
| Continuing worker | The next coherent task needs the same live state or costly tacit model | Refresh changed inputs/decisions; do not carry stale assumptions forward |
| Reference-withheld producer | The claim concerns novel generation or transfer without a particular reference | Specify which reference is withheld and what the producer legitimately receives. Withhold answers, not the quality bar: the producer still gets the baseline's format, depth and section structure |
| Separate assessment | A consequential judgment benefits from someone who did not produce the artifact or see its verdict | Record shared inputs/model assumptions and remaining correlation |

Keep tightly coupled UI/state/model work together until a durable intermediate
artifact makes the boundary useful. Small prompts are not automatically independent
tasks. Do not parallelize conflicting writes or give each fresh worker the entire
history. Use [the isolated assignment](../assets/prompts/isolated-assignment.md)
where helpful; the ordinary seven-element brief remains valid.

## State exposure honestly

Earlier conversation, attachments, inspected files, shared memory and retrieved
answers count as exposure. A new turn or an instruction to read something later
cannot remove prior exposure. Describe the exact withheld material, allowed input
set, known prior access and host enforcement. A fresh session with only the issued
inputs supports a task-context claim; broad workspace/tool access can still limit it.
Record UNKNOWN when access cannot be established. No setup here proves absence of
training-data contamination or changes the model's capability.

Distinguish observed exposure, material withheld by the setup and unknown access.
Do not describe instruction-only isolation as verified access prevention. A judge
must see the artifact and applicable criteria; it can be shielded from the producer's
verdict without being shielded from those necessary inputs. Different IDs, models
or wording alone do not establish independence. Legitimate shared references do
not by themselves invalidate separate review; state the relevant correlation.

When the producer assesses its own output, label that judgment SELF-ASSESSED in
the native return, including worker and specialist returns. If acceptance depends
on independent judgment, obtain the review required by the actual project. Where
another participant adds value, prefer a separately derived assessment. Otherwise
retain the self-assessment limit and use existing acceptance authority; add no new
Owner ceremony, mandatory team size or claim that all self-checks are worthless.

## Check the artifact's relationship to its reference

Before validating a generator, blueprint, repair or method, ask how the artifact
under test was produced. Record producer, revision, allowed/known reference access,
derivation (COPIED, ADAPTED, INDEPENDENT or UNKNOWN with a defined meaning), and the
claim being assessed. Use source-linked prose/records; no new JSON field or schema
is required. Relabeled numbers or changed wording do not establish novel transfer.

A copied/adapted reference can support faithful reproduction or an explicitly
allowed task. It cannot alone establish unseen generalization or independent
generator validity. A new setup is not proof that a producer lacked reference
access. Preserve useful correctness evidence while restricting the broader claim.
Apply the Owner's actual criterion; ask only about a consequential unresolved
meaning, rather than declaring every use of a reference invalid.

Trace upstream derivation too: a fresh producer cannot make a reference-derived
blueprint, dataset or oracle unseen. State which relationship the independence
claim concerns. Shared authorship/model assumptions can remain even when the
specific reference items were excluded from the producer's issued inputs.

Keep the existing product (the baseline) separate from the content source. A
producer given only the content source can match its facts and still fall far
short of the product's depth. Name both inputs in the brief. Judge the result
against the baseline section by section, using the same counting method on both
files. The coordinator who issued the work does not repair the artifact under
test. A repair goes back as a new brief. Only a typo-level fix that changes no
meaning, key or number may instead be labelled COORDINATOR-EDITED and shown to the
assessor.

## Make graded judgments and corrections usable

Identify required parts before rolling up a multipart verdict. Define the actual
scale and consequential edge cases. One conservative example is: all required parts
MET gives FULFILLED; some MET and some NOT_MET gives PARTIAL with named gaps; all
NOT_MET gives NOT_FULFILLED; any unresolved required part gives UNKNOWN while
retaining known coverage and misses. If a domain uses another rule, specify it.
Do not hide a known failure behind UNKNOWN or infer full coverage from one match.

Correct by stating the violated rule and illustrating it on invented/different
data. If teaching requires the actual target answer, identify that row as exposed;
later agreement on it cannot establish unaided transfer. Use an unexposed changed
condition to assess transfer where useful, not a fixed question quota.

For consequential checks, record a source-derived expectation and method before
seeing the return when feasible. Withhold it from the worker if independence is
the point; do not put a supposedly private key in a shared readable packet. Treat
expectations as falsifiable, not automatically authoritative. Disclose when a check
was derived after reading the worker's explanation.

## Adjust support from separate observations

Track input access, return-format reliability, method execution and substantive
judgment separately. Repeated clean receipts can justify reusing a reviewed brief
family and reviewing its changed parameters. They do not establish judgment in a
new domain. Keep every issued packet self-contained, with purpose, current inputs,
boundaries, material method and return condition. Remove repeated boilerplate, not
the reason or a load-bearing decision.

Restore fuller support for a changed task family/input, a meaningful miss, new
uncertainty or acceptance-critical judgment. Select further checking by actual risk
and requirements; no fixed number of successful returns, automatic model upgrade
or compulsory independent review is introduced. A uniform verdict set can motivate
a discriminating sample, but is not a presumption of error.
