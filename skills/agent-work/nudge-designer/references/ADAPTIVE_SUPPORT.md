## Treat capability as task-specific

Treat “low thinking,” a model name and a high-effort label as reported context,
not a measured universal rank. Record actual configuration only when observable.
Assess the particular understanding, tools and judgment this assignment needs.
Give an appropriate participant consequential synthesis; do not transfer that
judgment to a narrower worker merely by splitting it into commands.

When bounded execution needs are clear and recipient fit is limited or unestablished,
prefer GUIDED support. Use a representative task or contrast when its result will
change allocation/support. Inspect the artifact, not an ACK or a promise of care.
Keep acceptance criteria visible; withhold worked target answers when independent
judgment or transfer is being assessed. Add no compulsory calibration gate.

| Observation | Adaptation |
|---|---|
| Inputs/tools available; concrete task performed correctly | Continue authorized scope; reduce repeated scaffolding where evidence supports it |
| Confident assent without a usable witness | Request the specific source/computation/observation and a meaningful contrast |
| Computation works but a model decision lacks support | Keep useful execution; route that judgment to an appropriate participant |
| Tool/input access unestablished | Check relevant access or choose feasible bounded work; retain dependent execution NOT_RUN |
| A clear correction still produces substantive failure | Change method, task or participant under existing authority; do not repeat indefinitely |
| Genuine investigation with adequate task fit | Use OPEN support and discriminating evidence, without a preselected speculative repair |

A successful probe supports that task under those conditions. It does not qualify
another domain, establish independence or change the participant's runtime.

## Reduce avoidable decisions

For fresh task-local workers, artifact/reference exposure, multipart roll-up,
SELF-ASSESSED judgments and separate format-versus-judgment observations, use
[focused context guidance](ISOLATED_WORK.md). Freshness reduces history dependence;
it does not confer capability or prove blinding. Select the task boundary first.

Give one coherent deliverable, original conditions and a short WHY. For GUIDED
work specify the concrete operation, input interpretation, return condition and
self-check. Reserve consequential model/scope/authority decisions. “Check everything
carefully” is not a method. Use stable item/source IDs where needed.

Break large work at meaningful boundaries with usable context; do not atomize it
until the worker loses the parent outcome. Limit irrelevant history and simultaneous
unresolved choices. Prefer an example on different data over a target answer.

Specify parsing details when consequential: which records count, header/blank
exclusions, tokenization, units, coordinate frame or selected revision. Do not
invent a consequential missing definition; return it while retaining feasible work.
Keep the brief proportionate and warnings beside the decisions they affect.

The Designer should compile the relevant guidance into a self-contained issued
brief. Use the existing seven-element renderer/context selection where useful.
Do not require a narrower worker to read the whole profile library, choose among
all roles or reconstruct missing project meaning from history. Give direct needed
inputs and selected rules; retain actual project instructions. Load supporting
references only when a real unresolved definition calls for them. A short brief
still needs the purpose, witness, boundaries and return condition.

## Require evidence for claims

Choose evidence at claim granularity. For a row containing five factor claims,
one quotation or “all match” label need not support all five. Map each witness to
what it establishes. Shared evidence is legitimate when applicability is explained;
do not force repeated quotes when one reproducible relation supports several claims.

| Claim | Useful witness and remaining limit |
|---|---|
| Count or computed value | Source selection, algorithm/include-exclude rule and recomputed value; not a copied expected total |
| Interpretation | Relevant original passage plus the relation supporting the conclusion; quoting the disputed assertion alone is insufficient |
| Behavior works | Actual input/action and expected-versus-observed result on the claimed boundary, with source identity |
| Every item satisfies a condition | Accounted claim/item set, per-item or justified shared evidence, exceptions and unreviewed scope |
| No problem found | Checked scope/method and limits; no invented defect, exhaustive-coverage claim or fixed weakness quota |

Allow PASS/FAIL, MATCH/MISMATCH or native verdicts alongside substantive evidence.
Reject unsupported assent on meaning, not the presence of a binary column.
Renaming YES to MATCH does not improve evidence. A formatting lint cannot decide
whether a quotation or calculation supports the claim.

Select difficult, high-risk or uncertain cases for deeper challenge when justified.
Do not require exactly three weakest items, manufacture weaknesses in a small
correct set, or assume uniform verdicts must be wrong. Report a justified empty
finding set with coverage/limits when appropriate. A known contrary/control case
can test a method; do not misrepresent it as an observed defect.

The sender/coordinator should independently check consequential computable claims
where feasible, using authoritative inputs and a stated algorithm. Replaying the
worker's script checks reproducibility but may repeat its assumptions; distinguish
that from a separately derived check. Select checks by risk and governing project
requirements, without requiring another agent or recomputation of incidental fields.

## Check the sender and input path

Before attributing an error to the worker or source corpus, check which artifact
arrived and how it was interpreted. Wrong revision, context, codec, units, paths
or permissions can make a conscientious computation wrong. The sender can supply
the faulty premise.

Preserve original bytes. Where decoding matters, use the declared codec and its
basis; keep UNKNOWN if not established and obtain/verify it as necessary. Decode
strictly into a separate working view. Do not ignore/rewrite offending bytes or
silently try codecs until output looks convenient. Successful decoding establishes
decodability under that codec, not the intended encoding or content correctness.
Binary artifacts need their appropriate reader.

Use actual input bytes/revision, parser and units for counts or interpretation.
A copied expected count, filename or checksum is not an independent check. Correct
the input/view and reassess affected conclusions before blaming a benchmark or learner.

## Separate receipt from acceptance

Where chat cannot be copied reliably, choose accessible exact artifacts or a
manifest and a short native receipt identifying assignment, locator(s) and computed
digest(s). Verify recipient access; a sender-local path is not automatically shared.
Keep the actual issued packet and correction history.

For byte identity compute SHA-256 over file bytes. This differs from canonical
JSON intent/plan binding and the adapter's prepared-content digest; name the
representation. Verify receipts against returned artifacts rather than copied
checksums. One file and a fixed SAVED line can suit a particular UI; multiple
files or an existing native format can suit another. Add no universal transport ritual.

Receipt, readability, claim evidence, independent checking and Owner acceptance
are distinct facts. A digest cannot establish execution, source truth, capability
or acceptance. A missing reader/codec limits affected assessment; report the actual
restriction without inventing results or blocking independent work.

## Correct the cause and adjust support

Inspect returns against the outcome. Retain useful correct work and exact issued/
native history. Name the causal gap and give a visible correction or child assignment
through the existing process.

| Gap found | Next useful response |
|---|---|
| Wrong/unreadable/different input | Correct sender delivery, identity or interpretation first; rerun affected claims |
| Missing evidence for a conclusion | Request the missing discriminating observation/computation with exact scope |
| Missing prerequisite understanding | Narrow/scaffold the task or reserve that judgment with an appropriate participant |
| Repeated substantive failure after clear correction | Change method, task or participant; keep successful independent work |
| New original condition/Owner amendment | Reconcile meaning, revise current bindings and visibly correct delivered instructions |
| Corrected target example reveals its verdict | Mark that target exposed; teach the rule on different data and use an unexposed case if assessing transfer |
| Feedback suggests a reusable lesson | Assess generality, counterexamples and actual change authority before modifying a shared skill/protocol |

Do not assume every mistake is “low thinking,” a new session fixes it, or more
passes improve quality. Do not conceal an acceptance/architecture decision inside
mechanical steps. Honor actual project iteration/qualification/approval requirements
without installing a default gate or timer here.

## Apply across domains

| Work | Concrete support | Check that matters |
|---|---|---|
| UI | Current entrypoint/action, state identity, trace method | Ordinary interaction and contrary state/path evidence, not handler existence |
| Data review | Readable representation, record rules, claim IDs | Source-derived computation and exceptions, not a reported total |
| Teaching | Stipulated model, conceptual target, contrast | Relation supporting the concept; arithmetic differs from learner understanding |
| FEA | Units, load/boundary assumptions, bounded reference | Numerical reproduction and model applicability remain separate |
| Recovery/coordination | Original aim, current records, tools, authority | Reconciled differences and feasible work; reconstruction differs from repair execution |

## Pilot basis and limits

The [NLM pilot report](https://github.com/reallakshman19/CoordinatorLandingpage/issues/97#issuecomment-6253852158)
reports shallow P1, a usable GUIDED P2 table still needing two corrections, file
receipts and a sender-side cp1252 interpretation problem. The
[P3 result](https://github.com/reallakshman19/Grade9v3.5/issues/300#issuecomment-6255851612)
reports blanket factor assent alongside remaining content concerns.

These motivate design choices, not a causal GUIDED-versus-OPEN effect or model
benchmark: task, session, inputs and correction changed. A usable format and
stronger guidance did not establish error-free review. Treat fixed weakness counts,
one-file receipts and particular algorithms as applicable examples. The
[held PR #439](https://github.com/reallakshman19/Common/pull/439) remains reference
material, not imported authority or a runtime dependency. This broader update
follows the later direct Owner request to generalize the lessons and update.
