## Start and retain ownership

Use this guide when the Owner wants execution through workers, rather than only
a proposed plan. Use [the Oracle prompt](../assets/prompts/oracle.md) to start and
[the episode aid](../assets/prompts/episode.md) only for gaps in native records.
Keep the Owner's interface short; Oracle maintains the working state and sources.
Select Task Decomposer separately if a neutral map helps. Both skills work alone.

Oracle is a responsibility, not a capability or permission designation. Retain
the whole outcome, consequential model/architecture decisions, shared state and
integration. Reserve or route a judgment that available evidence cannot justify.
The Owner should not have to repair each brief or join component results by hand.

Establish the actual source/candidate, input, environment and original failed
behavior. Distinguish previous reported results from work executed now. Check the
available tools, channel and existing authority before selecting an action; a
restriction applies to its dependent work. Do not create new approval ceremonies.

Record intended and actual participant configuration separately, including model,
reasoning setting and source of the observation, or UNKNOWN. A role prompt does
not set a host configuration. A rehearsal on default agents can establish a local
application result without qualifying an intended low-thinking configuration.

These are adaptive responsibilities, not fixed phases, a required team size,
automatic model upgrade or prescribed number of successful returns.

## Prepare executable work

Choose the next uncertainty whose resolution can change direction. Write the
question and plausible alternative explanations before prescribing a remedy. A
short task can still conceal difficult model or measurement design. Keep that
design with Oracle or a suitable specialist until a worker has a usable method.

Check that the observation can distinguish the alternatives. Establish coordinate,
event-order, unit, page, identity or comparison conventions where consequential.
Try a cheap read-only control or source-level check when useful; report a proposed
method as unexecuted if it has not run. Specify how a contrary observation would
change the conclusion. A test that a copied answer trivially passes is inadequate
for unseen-transfer claims; trace upstream artifact/reference derivation too.

At a useful boundary, prepare one coherent deliverable using the seven-element
[assignment](../assets/prompts/assignment.md). Include necessary WHY and upstream
decisions, explicit input/state identity, a concrete GUIDED method when needed,
positive/negative evidence and a return condition. Keep coupled UI/model/state
decisions together until a durable output supports a useful handoff. Use a fresh
worker to reduce remembered-history dependence, not to remove necessary knowledge.

Read the actual recipient view using [the pre-send check](../assets/prompts/brief-check.md).
Remove repeated boilerplate, not load-bearing conditions. Walk its input/tool
instructions. Keep a reusable family and verify changed parameters rather than
re-authoring every packet. Prefer an explicit source artifact to retelling a chat.

Freeze the issued view and source/binding references. Send only through an actually
authorized host or manual channel. Record who sent what to whom and how the return
is found and correlated. A missing channel/watch is a delivery problem; another
worker prompt does not fix it. The skill neither launches nor monitors agents.

## Read a return and adapt

Inspect the returned artifact and decisive observations, not only its status,
hash, count or explanation. Preserve raw bytes/native reports; use existing
`bind`/`receive` support where appropriate. Its worksheet is not semantic approval.
Check source revision, scope, measurement validity and important computable claims.
Keep input access, format, method and substantive judgment as separate observations.

For each material result, say which claim changed and why. Select the useful
response rather than repeating an identical task:

| Actual finding | Useful response |
|---|---|
| Evidence supports the method and expected invariant | Retain useful work; continue the next affected task |
| Sender supplied wrong/stale/inaccessible input | Correct the input/view and reissue only affected work; retain the old receipt |
| Method cannot discriminate or observes the wrong state | Redesign the measurement with Oracle/specialist; do not blame worker compliance |
| Contrary observation falsifies the current explanation | Revise the explanation and next task visibly; do not instruct a speculative fix |
| Correct local artifact leaves an integration failure | Retain the artifact and address the missing consumer/state interaction |
| Consequential judgment remains unsupported | Reserve it, obtain suitable evidence/expertise or report the affected limit |
| Delivery/transport failed | Fix the actual route/correlation while preserving original artifacts |

Return drift, improvement, new issue or assumption conflict to the original
obligation. A discovery is not automatically in scope, a blocker for everything
or permission to patch. Continue authorized independent work. A blocked action
reports the attempt, observed restriction, affected scope and feasible next action.

Preserve issued history; update the current direction and only affected working
objects. Use `impact` after substantive intent change and rebind revised plans.
Do not invent map/plan revisions when only evidence status changed. A second
worker receives the needed predecessor artifact, not necessarily the whole chat.

## Verify the integrated result

Return to the original user interaction, question or output on the actual candidate
and preparation. Preserve meaningful negative cases and relevant previously working
behavior. A forced click, easier segment, changed benchmark, copied solution or
weakened assertion cannot establish the original claim.

Separate component correctness, integrated operation, independent review and
Owner/release acceptance. A producer's judgment stays SELF-ASSESSED. Select separate
assessment when useful/required, define its input coverage, and do not promote a
prompt-only assessment to full-artifact review. Shared references and prior access
must remain visible; instruction-level isolation is not verified access prevention.

End with the actual result, remaining parent outcomes, current source/start
reference and next feasible work. Completion of this loop does not imply completion
of the whole programme. A useful pilot contains an actual return interpreted into
continuation and resulting evidence, not only a reconstruction or prepared packets.

## Measure assistance and value

Record actual assistance: brief repair, input projection, environment repair,
manual transport, hidden verification or a decision made by someone else. Attribute
it to that participant. This is evidence of where support is needed, not a reason
to hide a successful intervention or declare the whole attempt worthless.

Capture available elapsed time, correction loops, coordinator effort and remaining
Owner work. Mark unavailable token/cost measurements UNKNOWN. Distinguish method
execution from consequential judgment; neat returns do not establish domain fit.
For a causal/ROI claim, use comparable tasks/baseline and include coordination cost.
A single successful loop without a comparison supports feasibility, not an effect.

## Select domain evidence

Keep this loop common; adapt the decisive evidence rather than creating mandatory
UI, logic, teaching or FEA phase counts:

| Domain | Useful integrated evidence | Important distinction |
|---|---|---|
| UI/navigation | Original input/action, actual hit/state trace, correct destination and recovery | Source handlers or keyboard success do not prove the original pointer interaction |
| Logic/data | Event-order or boundary witness, invariant and real consumer result | Happy-path unit checks do not establish stale/cancelled/state-transition behavior |
| Learning materials | Accurate material, prerequisite/transfer checks and actual learner responses where claimed | Author/reviewer agreement does not establish learner understanding |
| Numerical/FEA | Units, assumptions, analytic/reference comparison and application limits | Numerical agreement does not certify the physical model or engineering acceptance |

Use [the LFEA pilot entry](../assets/prompts/lfea-pilot.md) for that real-source
case. Its missing trace/runtime/authority must be established at use; it is not
evidence that a browser diagnosis or repair has already run.

## Owner-selected ChatGPT-agent activity duty

When the Owner selects standalone delivery with the ChatGPT-agent activity rule,
the executing **ChatGPT agent** runs its own episode recorder at turn boundaries
and useful checkpoints. Oracle ensures the issued brief retains that duty,
inspects the returned observations and surfaces a due BuddyRunner recommendation.
Oracle is not a background worker and cannot observe another agent's hidden time
or calls. Without an Oracle, the executing agent owns both responsibilities.

Suggest BuddyRunner after **more than five distinct GitHub-access turns OR more
than 35 recorded active-turn minutes**. Keep each agent/project episode across
subtasks; do not count calls as turns, sum separate agents or reset per nudge.
Record actual surface and observation basis; ChatGPT Work and other surfaces are exempt; UNKNOWN applicability must remain
explicit, rather than being claimed as an established exemption. An in-scope Oracle tracks its own episode separately.
Retain missing host IDs/timing as UNKNOWN/gaps, not fabricated zero or precision.
A known observed lower bound over either threshold still requires a suggestion.

Use the separately selected delivery protocol's recording/check support when
available; no import or runtime dependency is added here. Retain the actual
recommendation reference and counter snapshot in native records. Recommend once
per episode without automatic handover, a new permission ceremony or global work
stop. Metrics measure activity, not reasoning quality. Do not claim this prose
recipe installed host hooks, dispatched a worker or measured private thinking.
