## Choose a useful context boundary

Prefer fresh task-local workers for a coherent deliverable with explicit inputs,
necessary understanding and a checkable result. Minimize dependence on remembered
conversation, not the knowledge needed for correctness. A fixed count, format,
observation recipe or well-established implementation can fit this arrangement.

Keep coupled model/state/architecture decisions together until a durable output
can be consumed correctly without recreating the whole investigation. Repeated
tiny handoffs can cost more and lose more meaning than one coherent task. A fresh
worker may consume a pinned predecessor artifact; dependent work need not inherit
the predecessor's full chat. Do not force a size, number of tasks or fresh session.

For each useful cut ask: what travels, what is reserved, what evidence checks the
result, what state must stay consistent, and what would invalidate the artifact?
Use existing `understanding`, `decision_refs`, task boundaries, acceptance and
source/coverage records. No participant-exposure JSON schema is added.

## Compose the two independently selected skills

1. Reconstruct the original purpose, source conditions, useful work and unknowns.
   Distinguish actual source findings from reported results and proposed remedies.
2. Design the task map and useful frontier. Retain integration and future outcomes;
   scope missing facts to affected work. Supply a tested measurement/method or
   reserve its design when a narrower worker would otherwise invent it.
3. For a selected task, prepare its neutral design/map binding, accessible original
   inputs and necessary upstream decisions. Include relevant state/revision and
   limits. Link detail rather than repeating all history. Check the recipient can
   actually read binary/trace/source inputs through available tools.
4. If separately selected, Nudge Designer consumes that source packet and prepares
   participant-specific GUIDED/OPEN support and native return instructions. Oracle
   compares the brief with the map: purpose, task identity, source conditions,
   dependencies, reserved judgments, evidence and unresolved parent outcomes.
   A consumer's revised task meaning is a visible proposal, not a silent rewrite.
5. Send through the actual authorized/manual channel and preserve issued snapshots.
   Keep assignment, tracker and reply mapping explicit where relevant. The skills
   do not dispatch or synchronize each other's objects.
6. Inspect returned artifacts, not only COMPLETE, ACK or a digest. Assess which
   claim changed, what is unverified and which tasks remain useful. Update affected
   map and downstream plan meaning visibly; run each tool's impact where useful.
   Preserve old bindings and actual results. Review the integrated outcome separately.

When the Owner requests execution, carry these responsibilities through actual
work rather than returning only the map.
Use [the Oracle continuation prompt](../assets/entry-prompts.md) to make that scope
explicit. Before delegating, establish who designs the discriminating observation,
who sends/watches the actual channel, who interprets returns and who checks the
integrated result. Oracle retains any unallocated responsibility. A smaller brief
does not remove a difficult measurement/model decision.

When a return contradicts the current explanation, revise the explanation and next
useful task. When the sender's input or measurement failed, correct that cause
before repeating work. A correct component may expose missing integration instead.
Keep the change linked to evidence and original obligations; discoveries do not
automatically expand scope. Preserve issued artifacts and update only affected
working meaning. Status-only evidence need not cause a semantic map revision.

Record concrete assistance, actual versus intended configuration and available
coordination/correction effort. Do not attribute a parent's input projection,
brief repair or verification to unaided Oracle operation. Default-runtime success
supports that application; it does not qualify a low-thinking configuration or
establish ROI without comparable evidence. Keep these facts in native records,
not a compulsory new schema. An optional consumer must retain these duties even
when its runtime only prepares packets and checks structure.

These are application responsibilities, not mandatory phases, gates or a runtime
controller. Both skills still work alone. No native converter, shared import,
automatic reconciliation or permission service is implemented by this recipe.

## Distinguish focused context from blind evidence

For ordinary execution, give the worker all load-bearing inputs and decisions.
For transfer/generation testing, name the specific reference/answers withheld and
record actual setup, prior exposure and UNKNOWN access. Earlier conversation or
files already read count as exposure; an instruction to read later cannot undo it.
Fresh session/issued-input isolation supports only that task-context claim; shared
workspace/tool permissions and training-data exposure can remain unknown.

Track artifact-under-test producer, derivation and reference relationship before
choosing a validation task. Reference-derived matches can show reproduction but
cannot alone establish unseen transfer. Define the Owner's actual claim. Label a
producer's judgment of its own artifact SELF-ASSESSED and preserve review limits.
Select separate assessment when required/useful, without a default agent count.
Trace upstream blueprint/dataset/oracle derivation as well: a fresh worker does
not remove a shared source or premise from those inputs. Name the specific
relationship being assessed rather than claiming universal independence.

## Observe grounding without inventing competence

Keep input access, return-format reliability, method execution and substantive
judgment separate. A neat receipt can support reusing a brief family; it cannot
qualify a new model decision. Preserve concise WHY and necessary context in each
fresh brief. If a worker fails, inspect sender inputs/method before attributing
capability. Change the affected method/task/participant when evidence warrants it.

[Decomposed Prompting](https://arxiv.org/abs/2210.02406) supports studying modular
subtasks, while [Lost in the Middle](https://arxiv.org/abs/2307.03172) and
[multi-turn research](https://arxiv.org/abs/2505.06120) motivate selective context
and explicit decisions. These task-specific studies do not establish that every
fresh smaller task improves a low-thinking model. Measure useful result, correction
effort, context/handoff cost and retained integration in the actual application.

## Owner-selected ChatGPT-agent activity duty

When the Owner selects standalone delivery with the ChatGPT-agent activity rule,
the executing **ChatGPT agent** runs its own episode recorder at turn boundaries
and useful checkpoints. Oracle ensures the issued brief retains that duty,
inspects the returned observations and surfaces a due BuddyRunner recommendation.
Oracle is not a background worker and cannot observe another agent's hidden time
or calls. Without an Oracle, the executing agent owns both responsibilities.

Suggest BuddyRunner after **more than five distinct GitHub-access turns OR more
than 35 recorded active-turn minutes**. Keep each agent/project episode across
subtasks; do not count calls as turns, sum separate agents or reset per nudge.
Record actual surface and observation basis; ChatGPT Work and other surfaces are exempt; UNKNOWN applicability must remain
explicit, rather than being claimed as an established exemption. An in-scope Oracle tracks its own episode separately.
Retain missing host IDs/timing as UNKNOWN/gaps, not fabricated zero or precision.
A known observed lower bound over either threshold still requires a suggestion.

Use the separately selected delivery protocol's recording/check support when
available; no import or runtime dependency is added here. Retain the actual
recommendation reference and counter snapshot in native records. Recommend once
per episode without automatic handover, a new permission ceremony or global work
stop. Metrics measure activity, not reasoning quality. Do not claim this prose
recipe installed host hooks, dispatched a worker or measured private thinking.
