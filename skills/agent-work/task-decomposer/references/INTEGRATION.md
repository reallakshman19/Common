# Independent upstream module

Task Decomposer owns proposed task meaning and relationships. A consumer decides
how to guide or execute that work under its own selected rules. Installation and
execution of this package do not require Nudge Designer or any delivery protocol.

| Task Decomposer output | Consumer responsibility |
|---|---|
| Original goal, typed items, sources | Reconstruct against original authority; retain uncertainty |
| Coherent task and boundary reasoning | Preserve meaning or return a visible refinement proposal |
| Required understanding/open decisions | Select appropriate participant support and reserved judgment |
| Dependencies, contrast, integration claim | Choose a useful method and evidence for the actual assignment |
| Map/task/revision binding | Preserve issued identity and actual native returns |
| Scoped impact candidates | Reconcile meaning and continue independently useful work |

## Optional Nudge Designer consumption

Select it explicitly. Give it the neutral `render` output plus the pinned map and
relevant original sources. It can already read ordinary source material. Treat
the decomposition map as a SOURCE/proposal, not an OWNER instruction or accepted
product evidence. Reuse the existing intent/plan and source references when they
remain valid; preserve original conditions and task identity.

Ask Nudge Designer to choose participant-specific GUIDED/OPEN support, concrete
methods, evidence witnesses, the seven assignment elements and native return
handling. Leave source/model/scope conflicts visible for correction. A task can
produce several nudges, and a coherent nudge may support several mapped claims;
avoid a compulsory one-to-one mapping or automatic issue creation.

The Markdown packet is neutral source input, not native Nudge Designer JSON. This
version does not import its schema, generate its objects, invoke it, send a nudge
or synchronize status. No existing Nudge Designer file is changed. A fully native
adapter, if later useful, is a separate versioned consumer contract.

The neutral export is a complete source packet, not necessarily the worker-facing
prompt. Ask the consumer for a proportional operational view with links to detailed
context. Inspect that view for repeated conditions, concealed decisions and missing
original inputs; successful validation alone does not show useful condensation.
The [forward assessment](../examples/forward/ASSESSMENT.md) preserves an actual
verbose native consumer output and a separately labeled compact parent reference.

## Without a consumer

Return the task map and selected designs directly. A human, capable agent or
another planner can use the same source-linked result. Follow actual execution,
domain and review requirements; design labels do not grant any permission.

## Feedback

Keep native evidence in the actual project format. Reconcile it against the issued
map/task and original sources. Update relevant typed items/tasks in a new revision,
run impact, review undeclared dependencies and issue visible corrections. Evidence
can justify KEEP, split/merge, discovery or changed allocation without a mandatory
extra pass or per-task approval. Retain deferred and independent useful work.
