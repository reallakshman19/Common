This synthetic tabletop checks candidate instruction behavior. It is not product acceptance, a participant admission test, a browser/transport qualification or proof of production custody.

## Inputs and requests

Both fresh agents received the same local toy project. One followed Common START_HERE and relevant modules; the other followed the staged Codex adapter. Neither authored the instructions or received an intended answer.

- Owner: compare two existing XML geometry inputs first; field transfer and CII writing are deferred. Direct Oracle appointment permits planning only, without revoking an incumbent writer.
- Native source: WBS3.1 viewer delivered according to its author; consumer trial absent. Mina retains shared UI custody. A later Owner decision allows disjoint WBS3.2 matching exploration.

- Proposed MAP5.1 has not been shown to supersede WBS3.1; MAP5.2 consumes candidate matching, MAP5.3 transfer planning is later.
- Accessible synthetic input: source node S5 at x=5, target nodes T0=0 and T10=10, target element E0 connects those endpoints. A separate private input is unavailable.
- Implementation checks exact physical target nodes first, then strict element interiors. The actual local toy run returns `SEGMENT_ONLY / E0 / target_node=null`. It contains no SVG renderer or full manual-anchor workflow.

The four requests were: (A) a newly appointed Oracle chooses the next prototype/WBS direction; (B) a new builder investigates possible interior-point node mislabelling in one pre-resolved WBS3.1 preparation slice; (C) an established participant continues an already-authorized label-only documentation change with its own prior source understanding; (D) a candidate successor prepares read-only continuity with unavailable private input.

## Validation boundary

Existing Oracle continuity and Nudge Designer tests remain source/schema/CLI checks, distinct from this rehearsal. No new test was added merely to match the new wording. Windows checkout line endings and sparse reference availability were corrected for hash/link checks without changing fixture Git objects. A local Windows symlink-creation privilege failure is recorded separately; its assertions require a capable host. Hosted check results must be read at the actual candidate.

For an unseeded repeat, give a fresh participant only the input facts, runnable toy source and request; withhold this observations section. Evaluate the resulting source-based reasoning and actual actions, rather than counting questions or grading a participant.
