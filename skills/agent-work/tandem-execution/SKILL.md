# Tandem Execution — Agent A → Agent B

Use when two agents are assigned to complete the same bounded engineering outcome. Both are execution agents, not one builder and one commenting agent. There is one task, one candidate lineage and one current writer. A owns the first candidate; B owns the final result. All agent-to-agent handoffs and final delivery use the assigned Google Drive folder. No alternative relay, separate approval queue or new WBS.

1. **Assign once.** Fill the [assignment](templates/ASSIGNMENT.md) with original requirements, baseline, permitted files/actions, A and B, exact Drive folder, acceptance cases, forbidden actions and a bounded execution budget. Explicitly grant A first-turn writes and B successor-turn writes once A has stopped writing and the Drive checkpoint is recoverable. No repeat approval for routine reproduction, fixes, tests or handoff. Do not infer permissions that were never granted.
2. **Agent A executes.** Use [A prompt](templates/AGENT_A.md). Independently derive expected outcomes; reproduce material defects, implement fixes and execute positive and negative controls. Deliver real source, runnable tests, inputs and evidence, not suggestions. If A cannot finish a feasible substep, capture the exact failure and provide the best usable checkpoint. Stop writing before publishing the final handoff marker. A does not resume writes or receive repair work back.
3. **Drive handoff.** Use [Drive contract](DRIVE_HANDOFF.md) to publish A's one cumulative checkpoint, including source/patch, manifest and a concise remaining-work note. Upload binary/native artifacts, verify actual upload, publish the READY marker last, and stop. The marker is a completion signal, not a separate approval. B reads the same folder, verifies bytes and recovers missing evidence without asking A to repeat routine work. No chat attachment, GitHub comment or sandbox link is the handoff.
4. **Agent B executes to closure.** Use [B prompt](templates/AGENT_B.md). Start from the recoverable A candidate, not the original baseline alone. Reuse trustworthy work; derive at least one material contrary case from original intent, rerun affected checks, fix all surviving in-scope defects including A's mistakes, add meaningful regression coverage and verify the cumulative output. If A solved the defects, contribute a substantive executable integration/negative control; do not manufacture code churn. B never hands routine repair back to A. Repair locally and keep going within the granted scope/budget.
5. **B delivers.** Publish B's cumulative final candidate, native evidence, unresolved limitations and A→B lineage to Drive, using [final return](templates/FINAL_RETURN.md). B owns the final result. A and B each state what they authored; B's own edits are self-checked. Do not claim unexecuted checks, independent acceptance, merge or release. The task's pre-existing acceptance policy remains unchanged; this recipe adds no third participant or additional approval.

**No artificial blockers:** missing report formatting, unavailable historical logs, mismatched finding IDs, old green tests, unavailable browser/CI, or a correctable patch conflict are not reasons to stop all execution. Recover original source where permitted, derive tests, use the strongest available runtime, narrow claims honestly, and finish unaffected work. If shared bytes, permissions or actual conflicting writes make an action impossible, stop that action only; package the best runnable result and a precise recovery instruction. Never fabricate evidence or bypass a real security or write boundary.

Read [README](README.md), [protocol](PROTOCOL.md), [methodology](METHODOLOGY.md) and [worked golden](examples/golden/WORKED_HANDOFF.md) for the full pattern. For established agents, use only the changed assignment/checkpoint. No extra onboarding, repeated report or mandatory ceremonial step.
