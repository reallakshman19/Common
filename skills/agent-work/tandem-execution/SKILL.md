# Tandem Execution — Agent A and Agent B

Use for one bounded engineering outcome assigned to two execution agents. Both fix, test and deliver; neither is a report-only participant. **PARALLEL is the default.** No mandatory dependency on A's delivery before B can implement. The only final candidate owner is B. One existing task; no new role, controller or approval registry.

## Execute

1. **Assign once.** Use the [assignment](templates/ASSIGNMENT.md). Bind the original outcome/source C0, A/B, a common authorized Drive folder, scope, protected invariants, finite done-list and practical convergence boundary. Both agents have implementation authority immediately in PARALLEL. Choose SERIAL explicitly only if B truly must continue a first working candidate. Authority is granted by the actual assignment, not this skill or a marker.
2. **Implement concurrently (default).** A and B each derive expected behavior, reproduce failures, modify their own isolated working tree/branch, execute native controls and repair regressions. A owns A1; B owns B1. Allocate complementary primary areas without forbidding necessary adjacent corrections. Existing valid local implementation is usable work, not a prototype because the peer is absent. Neither writes the other's workspace or a common mutable branch.
3. **Publish native work through Drive.** A uploads immutable A1 and A-READY.json; B uploads immutable B1 and B-READY.json when useful for convergence/recovery. Markers index actual artifacts, not execution permits. A missing marker does not block B's own implementation or recovery of verifiable native files. Both verify actual bytes. See [Drive contract](DRIVE_HANDOFF.md).
4. **B converges forward.** B reads available A and B candidates, verifies ancestry/source and actual diffs, selects the better correction against original intent, composes nonconflicting changes, fixes semantic conflicts, runs combined positive/negative controls and owns every remaining in-scope defect. Do not blindly concatenate patches. B may expand into unfinished A scope and finish without A. No routine B→A repair request. Do not force gratuitous code edits merely to show two contributions.
5. **Deliver at the assigned completion boundary.** B publishes one final candidate and B-FINAL.json: FINAL_COMBINED if actual contributions from both agents are retained (code or executable evidence); FINAL_B_ONLY if no A contribution was retained, with reasons; SERIAL_FINAL for a verified continuation of A's candidate. Report COMPLETE/PARTIAL separately from lineage and delivery. If A appears late, preserve it without automatically reopening a completed task. Never fabricate a contribution, run, receipt, acceptance or release. A does not take final ownership back.

## SERIAL (explicit selection only)

A builds C1; B can prepare independent tests and isolated recoverable work while A executes. Only mutation of A's candidate requires verified transfer or isolation. After A publishes a recoverable checkpoint, B incorporates it and fixes forward; if A cannot deliver, B can reconstruct the outcome from C0 or its own valid checkpoint. Do not convert SERIAL's shared-candidate custody condition into a ban on isolated implementation. A/B prompts and Drive handoff support both modes.

**Recovery, not blockers:** missing report, absent READY, slow/absent peer, ordinary conflict, missing test dependency, unavailable historical fixture, or browser/CI gap must not stop feasible authorized work. Recover locally; use authentic source and discriminating executable tests. Real permission, protected production actions or unsafe/unverified inputs constrain only affected actions. Work within scope and report actual limits.

Read [README](README.md), [protocol](PROTOCOL.md), [methodology](METHODOLOGY.md), [parallel worked example](examples/parallel/WORKED_HANDOFF.md) and [checklist](CHECKLIST.md) as relevant. Established agents continue their existing implementation; no new discovery round. All agent-to-agent artifact exchange and final native delivery use Google Drive. No extra acceptance roles or routine approvals.
