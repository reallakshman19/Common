# Review selected-response learning material

Use the original learning target/tile, verb definition, candidate items and any
stipulated formatting limits. Keep item demand, cue quality, subject correctness,
reference provenance and learner understanding as distinct claims.

## Declare exposure and evidence before verdicts

State what you saw earlier: candidate authorship, generated items, answer keys,
benchmarks, previous judge verdicts and relevant prior conversation/files. Name
UNKNOWN access rather than claiming a fresh judge from a role label. If exposed,
base the new assessment on exact supplied files and source locators, and say which
judgments remain correlated. File-only evidence does not erase memory or make the
review blind. Continue useful review; do not invent a separate participant.

## Inspect format/demand before interpreting subject correctness

For these items, first inspect possible non-subject routes to the keyed answer:

| Check | What to inspect | Limit |
|---|---|---|
| Length/detail | Actual option word counts; unique longest key or unequal qualification | A longest key is a signal, not automatically a defect |
| Reasoning markers | Because/therefore or an explanatory form present only in the key | Causal/argument wording may be required; do not ban it |
| Grammar | Parallel options, consistent stem completion, comparable tense/person | Matching grammar does not establish science |
| Verb-option relation | Explain needs causal reasons; justify needs an argument; retrieval can recognise a unit/sign | Apply the source definition and compound demand, not a rigid universal taxonomy |
| Shared question words | Substantive overlap unique to the key; possible answer by word matching | Legitimate terminology may survive inspection with a recorded reason |

Then ask: **Could the keyed answer be selected without the intended subject
knowledge?** Record the actual cue or explain why the proposed route is not
sufficient. Inspect the generator's actual script output when available, and
recompute consequential counts as useful; a generator's PASS is not the check.
Use any appropriate local tool; this skill has no dependency on Nudge Designer.

Proceed to the subject: derive the answer and rule application from original
givens/conditions, test misconceptions and check whether distractors are wrong for
substantive reasons. Do not stop physics review merely because a fixable format cue
was found. If an item is unanswerable as written, keep that demonstrated defect
alongside the subject checks that remain possible or NOT_RUN.

This is a useful order of attention, not compulsory agent passes or a new gate.
A true key can sit in a cued/off-demand item; a polished cue-free item can have a
wrong key. Neither receives an undifferentiated PASS. Correctness and usability
findings can coexist without calling the entire review unavailable.

## Return evidence at verdict level

For each verdict/item or a justified shared verdict group, include:

- Exact item/source locator, required demand and checked option form.
- Format/cue findings and subject derivation as separate evidence.
- Disposition, uncertainty and applicable exposure limits.
- **What plausible wrong result could survive this check?** Name a concrete
  residual risk and the contrast that would discriminate it, or explain why none
  survives within an explicitly exhaustive checked scope. Do not invent a defect.

A length/word-overlap check can miss a wrong physical model; answer derivation can
miss a lexical cue; agreement among exposed judges can repeat one premise. Use the
answer to select the next useful check rather than inserting generic caution text.
A correct finite proof may settle its stated claim while leaving learner transfer
unmeasured. Keep scope honest without a fixed weakness or reviewer quota.

The Owner-supplied G6–G8 note motivates these safeguards. Its reported 15/15 judge
agreement is useful application evidence, not independently inspected source truth,
a controlled comparison or proof that a non-fresh reviewer is independent.

With optional structured results, retain these explanations in existing claim `reason`/`limitations` and independence `basis` fields; no new schema or fixed wording is required.
