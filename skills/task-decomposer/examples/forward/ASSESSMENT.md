# Forward applications and limits

Two fresh Task Decomposer applications and one fresh Nudge Designer consumption
used synthetic local tasks. They saw raw issued inputs and the relevant skill
instructions, without worked examples, tests, verification material or other
applications' outputs. Model, reasoning effort and formal qualification were
UNKNOWN; this is not a controlled comparison of low-thinking models.

| Application | Native result | Evidence and practical limit |
|---|---|---|
| [Long workflow](long/reconciliation.md) | Six mapped tasks retain the original journey, repair, integration and future batch work; ordinary-path discovery precedes speculative repair | [Map](long/task-map.json), [original records](long/records.md); no actual product/browser reproduction |
| Independent long-work branch | An actual [keyboard note inventory](long/keyboard-help-inventory.md) was completed while missing ordinary-path inputs remained scoped to affected tasks | Its action labels come only from the supplied note; shortcut keys stay UNKNOWN |
| [Single hard problem](single/explanation.md) | One coherent `T-INVESTIGATE` task, KEEP, with exact source/revision and event-order conditions | [Map](single/task-map.json), [finite analytical checks](single/analysis-checks.json); no forced task count or repair architecture |
| [Unchanged Nudge Designer](consumer/reconciliation.md) | Read the neutral source packet and produced native intent/plan plus a GUIDED brief preserving the task | [Validation](consumer/validation.json), [seven sender checks](consumer/source-checks.json), [fit](consumer/fit.json); fit remains NOT_ESTABLISHED, qualification/execution authorization false |

The fresh single-problem application was not given Task Decomposer's worked
single-logic solution. The consumer read only its issued neutral map/design and
named source files, not Task Decomposer's implementation. It selected its own
participant support and method. Nothing invoked it automatically or converted
the map into native consumer JSON. No worker was dispatched by the prepared plan.

## Check substance as well as shape

The [parent design checks](parent-design-checks.json) replayed both maps and native
rendered packets, verified declared source byte hashes, and observed the independent
keyboard task as DESIGN_CANDIDATE with no blocking unknowns. The
[parent consumer checks](parent-consumer-checks.json) replayed native validation,
fit, binding and rendering exactly using unchanged Nudge Designer code.
The [parent JavaScript check](parent-javascript-check.json) actually executed the
synthetic literal helper under Node v24.19.0 for the original case and two contrasts.
That is separate from the agents' finite Python analyses. It does not establish
caller timing, production causality, a repair or ordinary application acceptance.

Condensation remains a usability limitation: the single neutral source packet is
1,685 whitespace-delimited words; the consumer's [native worker view](consumer/worker.md)
is 2,335. It preserves meaning but repeats context and does not demonstrate useful
worker-facing compression. The [compact operational reference](parent-compact-brief.md)
is a parent-authored refinement, not that agent's output, a second fresh application,
a dispatched brief or evidence of recipient performance. Guidance now distinguishes
full source context from a proportional operational view. No Nudge Designer code
was changed. A later actual recipient application is needed to assess usability.

## Preserve the changed-checker observation

While the long application ran, the parent added the descriptive `unallocated`
frontier field. Its [initial consistency receipt](long/consistency-result.json)
correctly recorded a frontier mismatch. The map, validation and task renderings
were unchanged. The [final separately named recheck](long/consistency-result-rerun.json)
records matching outputs and stable script/schema hashes before and after the run.
Both receipts are retained; the first result is not rewritten as a pass.

[Source-change metadata](tool-snapshots/change.json) distinguishes the final copied
script from the earlier script reconstructed by reversing that one edit. The
first-run script hash was not captured. Archived script snapshots are source
history, not a runnable copied package: their original relative schema layout is
absent here. Use the installed skill's `scripts/task_decomposer.py` for checks.

## Archive identity and interpretation

[Original issued inputs](issued-inputs.sha256.json) cover five raw files; the
[consumer input manifest](consumer-issued-inputs.sha256.json) covers seven issued
files. Parent verification confirmed those bytes stayed unchanged. The
[archive manifest](archive-sha256.json) covers 44 copied UTF-8 artifacts,
including native results, parent checks and tool snapshots. New assessment/manifest
metadata is identified separately. Hashes bind content; they do not authenticate
source authority or establish semantic correctness.

Native Markdown retains generated blockquote spacing, a consumer method-label
space and a final blank line. The unrestricted diff whitespace check reports
those archived lines; changing them would break the issued byte hashes and exact
render replay. Source/documentation checks exclude this byte-preserved archive.

Historical absolute workspace paths and native bindings are deliberately retained.
The `long/`, `single/` and `consumer/` relative files contain the archived bytes.
To replay source-bound checks elsewhere, explicitly map historical locators to
these files or create a new visibly revised packet; do not silently rewrite native
inputs or expect old absolute paths to resolve. Canonical map digests differ from
file-byte SHA-256 by representation, as specified in the contract.

These observations support the independent design/source interface and some useful
boundary choices. They do not qualify a performer or establish general planning,
UI repair, learner understanding, FEA validity, production acceptance or merge
readiness. The separate focused suite tests structural/tool behavior, not those
claims.
